# 蓝牙移植报告 —— Samsung Galaxy S6 (SM-G9209 / zeroflte, Exynos7420)

> 日期：2026-10-20
> 目标：mainline Linux 6.6 + Debian 12（GNOME 已可用，WiFi/显示/GPU/电池已通）
> 范围：只做静态分析 + DTS/config 改动 + 编译验证。**没有刷机、没有重启手机。**
> 结论状态：**可行，但被一个未实测地址（CMU_AUD 0x114C0000）卡住，需 Lead 用 loader 探一次。**

---

## 0. 一句话结论

S6 的蓝牙是 **BCM4358 combo 芯片的 BT 部分，走 UART4（`0x11460000`）**，
四线带硬件流控，GPIO 是 `BT_EN=gpf4-1 / BT_WAKE=gpr3-4 / BT_HOST_WAKE=gpa2-1`，
**没有独立 BT LDO**（和 WiFi 共用模组供电，WiFi 已通 ⇒ 这路电是有的）。

mainline 的 `hci_bcm` **可以用**，但**只能走 `hci_ldisc` + `btattach`，不能走 serdev**
（`samsung_tty.c` 根本没有 serdev 支持）。固件 `bcm4358A3_V0083.0138.hcd` 在 vendor 树里就有。

**唯一的硬阻塞**：BT UART 的时钟门控在 **CMU_AUD (0x114C0000)**，而这颗 CMU 在当前
板级 DTS 里是 `status = "disabled"`（"所有 CMU 先禁用"策略）。要打开它就得让内核
读写 `0x114C0000` —— 这个地址**不在已知死区**，但**也没有 loader 侧 `mrd` 实测记录**。
按"未实测地址不要从内核直接读"的约定，本次交付把 BT 默认关掉，**探测通过后再打开**。

## 1. 硬件接法（带 vendor 源码证据）

### 1.1 芯片型号：BCM4358（确实是 WiFi 那颗 combo 的 BT 部分）

vendor DTS `arch/arm64/boot/dts/exynos7420-zero_common.dtsi:1771`：

```dts
	bluetooth {
		compatible = "broadcom,bcm4358";
		gpios = <&gpf4 1 0	/*BT_EN*/
				&gpr3 4 0	/*BT_WAKE*/
				&gpa2 1 0xF	/*BT_HOST_WAKE*/ >;
		pinctrl-names = "default";
		pinctrl-0=<&bt_hostwake &bt_btwake &bt_en>;
		status = "okay";
	};
```

vendor 内核驱动 `drivers/bluetooth/bcm4358.c:377` 的 `of_match` 就是 `"broadcom,bcm4358"`
（`Kconfig:260 CONFIG_BT_BCM4358`，仅 zeroflte/zerolte 这类 4358 机型启用；
Note5/noble 用的是 `"broadcom,bcm4359"`，对应 `exynos7420-noble_common.dtsi:1877`）。

固件文件头里也自报家门，`bcm4358A3_V0083.0138.hcd` 偏移 `0x63` 起：
`"BCM4358A3 Samsung Zero EU UART"` —— 确认是 **A3 stepping + Android Zero 平台 + UART 传输**。

### 1.2 接口：UART4 @ `0x11460000`（不是 SDIO、不是 PCIe）

vendor `arch/arm64/boot/dts/exynos7420-zero_common.dtsi:129`：

```dts
	serial_4: uart@11460000 {
		pinctrl-0 = <&uart_bt_active &uart_bt_output_sleep &uart_bt_input_sleep>;
		status = "okay";
	};
```

vendor `arch/arm64/boot/dts/exynos7420.dtsi:595`（节点本体）：

```dts
	serial_4: uart@11460000 {
		compatible = "samsung,exynos7420-uart";
		reg = <0x11460000 0x100>;
		interrupts = <0 91 0>;                 /* GIC SPI 91 → virq 123 */
		clocks = <&clock 416>, <&clock 432>, <&clock 455>;
		clock-names = "gate_pclk4", "gate_uart4", "sclk_uart4";
		samsung,lpass-subip;
		uart-sclk-frequency = <117000000>;
		status = "disabled";                   /* 由 zero_common.dtsi 打开 */
	};
```

- **4 线带硬件流控**：`uart_bt_active` 覆盖全部 4 个脚
  （vendor `exynos7420-pinctrl.dtsi:192`，`gpz1-3..gpz1-0`，`pin-function = <2>` 即 UART 功能）。
  所以 TX/RX/CTS/RTS 都在，`btattach` 默认开 `CRTSCTS` 是正确做法。
- **主线对应节点已经现成**：`arch/arm64/boot/dts/exynos/exynos7.dtsi:350`
  的 `serial_4: serial@11460000`，`interrupts = <GIC_SPI 91 IRQ_TYPE_LEVEL_HIGH>`、
  `clocks = <&cmu_aud PCLK_UART>, <&cmu_aud SCLK_UART>`、`clock-names = "uart","clk_uart_baud0"`
  —— 和 vendor 完全对得上（Samsung 的 `gate_pclk4/gate_uart4/sclk_uart4` 就是主线的
  `PCLK_UART/SCLK_UART`）。**不需要改 `exynos7.dtsi`。**
- `bcm4358.c:45` 的 `#define BT_UPORT 4` 与 `uart4` 编号一致；
  它在 `bcm4358.c:246` 把 `s3c2410_serial_wake_peer[4]` 挂上自己的 LPM 回调，
  `drivers/tty/serial/samsung.c:1074/1127` 会按 `port->line` 回调 —— 即 BT 就是 UART4 这条。

### 1.3 GPIO：三个脚，全部落在**已实测可访问**的 pinctrl 块里

| 功能 | vendor 写法 | pinctrl 块 | 地址 | vendor 全局 GPIO 号 |
|---|---|---|---|---|
| BT_EN | `<&gpf4 1 0>` | `pinctrl_bus1` (BUS1) | `0x14870000` | **142** |
| BT_WAKE | `<&gpr3 4 0>` | `pinctrl_fsys1` (FSYS1) | `0x15690000` | **219** |
| BT_HOST_WAKE | `<&gpa2 1 0xF>` | `pinctrl_alive` (ALIVE) | `0x10580000` | **17** |

pin 定义的出处（vendor `exynos7420-pinctrl.dtsi`）：

- `:910` `bt_en: samsung,pins = "gpf4-1"; pin-function = <1>; pin-pud = <0>;`
- `:1199` `bt_btwake: samsung,pins = "gpr3-4"; pin-function = <1>; pin-pud = <0>;`
- `:76`  `bt_hostwake: samsung,pins = "gpa2-1"; pin-function = <0>; pin-pud = <0>;`

**这三个 GPIO 号是"算出来 + 实测对上了"的双重证据**，见 §2。

### 1.4 时钟：**唯一的风险点 —— CMU_AUD (0x114C0000)**

BT UART4 的 PCLK/SCLK 来自 **CMU_AUD**，不是 CMU_PERIC1：

- vendor：`exynos7420.dtsi:604` `clocks = <&clock 416>, <&clock 432>, <&clock 455>`
- 主线：`exynos7.dtsi:354` `clocks = <&cmu_aud PCLK_UART>, <&cmu_aud SCLK_UART>`
- 主线 CMU_AUD 节点：`exynos7.dtsi:657` `cmu_aud: clock-controller@114c0000`
  （驱动 `samsung,exynos7-clock-aud`，`drivers/clk/samsung/clk-exynos7.c:1290-1375`
   里 `GATE(PCLK_UART,"pclk_uart",...,ENABLE_PCLK_AUD,25)` / `GATE(SCLK_UART,"sclk_uart",...,ENABLE_SCLK_AUD,29)`）

**好消息**：`0x114C0000` 和已知死区（`0x14C00000..0x14CE0000`、`0x10570000`、`0x105D0000`、
`0x13650000`）**完全不在一个地址段**，也不是 `0x14Cxxxxx`。
如果 BT 走的是 UART1/2/3（`0x14C20000/0x14C30000/0x14C40000`，时钟在 `CMU_PERIC1=0x14C80000`）
那就彻底没戏；**幸好原厂把 BT 放在 UART4 上，绕开了死区。**

**坏消息**：当前 `exynos7420-zeroflte.dts:538` 明确写着

```dts
&{/soc@0/clock-controller@114c0000} {
	status = "disabled";
};
```

而 `of_clk_init()` 是**认 `status` 的**（`drivers/clk/clk.c:of_clk_init()` 里
`if (!of_device_is_available(np)) continue;`），所以这颗 CMU 现在**真的没有被初始化**。
把它改成 `okay` 会让内核在启动早期读写 `0x114C0000` —— 这是一个**未经实测**的动作。

> 补充说明：`pinctrl_aud@114b0000`（同属 AUD 块）在 DT 里一直是 enabled 且能启动，
> 但主线 `exynos_eint_gpio_init()`（`drivers/pinctrl/samsung/pinctrl-exynos.c:276`）
> 只做 `devm_request_irq` + 建 irq_chip，**并不读写 pinctrl 寄存器**，
> 所以它不能证明 AUD 块的总线可访问性。不能拿它当"已验证"。

### 1.5 电源：**没有独立 BT LDO**

`drivers/bluetooth/bcm4358.c` 全文**只操作三个 GPIO**，没有任何 `regulator_get()`
（全文 397 行，grep 不到 `regulator`）。vendor DTS 里也没有 `bt_ldo`/`bt_vdd` 之类的节点
（`grep -i "bt_ldo\|bt_vdd"` 在 zeroflte 全部 dts/dtsi 里无命中）。

⇒ BT 与 WiFi 共用 combo 模组的常供电。**WiFi（BCM4358 over PCIe）已经工作**，
说明这路电是通的，BT 上电只需要拉 `BT_EN`。

逐条解读：

   `drivers/pinctrl/pinctrl-exynos.c:1315-1390` 的 bank 顺序和 pin 数累加：

   | 控制器 | bank（pin 数） | 起始号 |
   |---|---|---|
   | 0 ALIVE | gpa0(8) gpa1(8) gpa2(8) gpa3(8) | 0 |
   | 1 AUD | gpz0(7) gpz1(4) | 32 |
   | 2 BUS0 | gpb0(5) … gpg3(4)（共 73） | 43 |
   | 3 BUS1 | gpf0(8) gpf1(8) gpf2(4) gpf3(5) **gpf4(8)** … | 116 |

   - `gpa2-1` = 16 + 1 = **17** ✓

   三个全中 ⇒ DTS 里那行 `gpios = <&gpf4 1 0 &gpr3 4 0 &gpa2 1 0xF>` 的语义**无误**。

## 3. mainline 可行性评估

### 3.1 `hci_bcm` 能不能直接用？—— 能，但只能走 ldisc

`drivers/bluetooth/hci_bcm.c` 同时注册了两种驱动：

- `bcm_serdev_driver`（`:1617`）—— **用不了**
- `bcm_proto`（`:1309`，`.id = HCI_UART_BCM`）→ 通过 `hci_ldisc` 给 `btattach -P bcm` 用 —— **这条能走**

**为什么 serdev 用不了（两个独立原因）**：

1. **`drivers/tty/serial/samsung_tty.c` 里 grep 不到任何 `serdev`**
   （`grep -n "serdev\|SERDEV"` 无输出）⇒ 这个 UART 控制器不是 serdev controller，
   `serdev_device_driver` 的 probe 永远不会被调用。
2. `bcm_bluetooth_of_match[]`（`hci_bcm.c:1598`）里**没有** `brcm,bcm4358`
   （只有 20702a1/4329/4330/4334/43430a0/a1/43438/4349/43540/4335a0/cyw4373a0/cyw55572）。

### 3.2 ldisc 路径下会发生什么（逐行核对过）

| 环节 | 行为 | 依据 |
|---|---|---|
| 流控检查 | `bcm_open()` 要求 `CRTSCTS`，`btattach` 默认会设 | `hci_bcm.c:449`；bluez `btattach` 默认 `CRTSCTS`（`-N` 才关） |
| 找 `bcm_device` | `hu->tty->dev->parent == dev->dev->parent` 匹配不上 ⇒ **`bcm->dev == NULL`** | `hci_bcm.c:465-490` |
| 于是不碰 GPIO/IRQ | `bcm_open` 里 `if (bcm->dev)` 整段跳过 | `hci_bcm.c:493` |
| **固件照样下载** | `bcm_setup()` 无条件调 `btbcm_initialize()` | `hci_bcm.c:581-597` |
| sleep VSC 跳过（不会空指针） | `bcm_request_irq()` 在 `bcm->dev==NULL` 时返回 `-ENODEV`，`bcm_setup_sleep` 不执行 | `hci_bcm.c:239-241` + `:685` |
| 波特率 | `bcm_proto.init_speed=115200`，**`oper_speed=0`** ⇒ 不会切高速，链路停在 115200 | `hci_bcm.c:1312-1313` |

`oper_speed = 0` 这点很关键，**正好规避了 SCLK_UART 可能不够快的问题**
（若 SCLK_UART 最终是 fin_pll 24 MHz，最高只能到 1.5 Mbaud，切 3 Mbaud 必挂）。

### 3.3 主线还缺什么（已全部补齐，见 §4）

| 缺的东西 | 处理 |
|---|---|
| `CONFIG_BT` 全关（原 `.config:1381` = `# CONFIG_BT is not set`） | 打开（见 §4.2） |
| `serial@11460000` 在板级 DTS 里没使能 | 使能 + 配 pinctrl |
| 没有 BT_EN/BT_WAKE/HOST_WAKE 的描述 | 加 gpio-hog + pinctrl group |
| CMU_AUD 被关 | **待探测后再开**（见 §0/§5） |
| **`CONFIG_SERIAL_SAMSUNG_UARTS=4`，UART4 是 index 4 会越界** | 用 DT alias 把 index 钉成 0（见下） |
| `CONFIG_SERIAL_SAMSUNG=m` | 改 `=y` |

> **`SERIAL_SAMSUNG_UARTS` 的坑（值得单独记一笔）**：
> `drivers/tty/serial/Kconfig:251` 里它是
> `int` 且**没有 prompt**，所以**没法从 `.config` 改成 5**（`make olddefconfig` 会
> 直接把它重置回 default 4）。而 `samsung_tty.c:1829` 的数组是
> `s3c24xx_serial_ports[UART_NR]`，`UART_NR = CONFIG_SERIAL_SAMSUNG_UARTS`，
> `:2065` 有 `if (index >= ARRAY_SIZE(...)) return -EINVAL;`。
> `index` 来自 `of_alias_get_id(np, "serial")`（`:2060`），没有 alias 时用递增的
> `probe_index`（`:2040/:2056/:2157`）。
>
> 因为 serial_0..serial_3 都是 `disabled`（不会被 probe），serial_4 天然就是 index 0。
> 但它依赖 probe 顺序，太脆。所以本次在 DTS 里显式加
> `serial0 = &serial_4;` 把 index 钉成 0 ⇒ 设备节点是 **`/dev/ttySAC0`**
> （**不是** vendor 那个 `ttySAC4`，注意别照抄网上的命令）。
> 这样既不用改 `Kconfig` 默认值（越界改动，不在本次范围），也不会越界。

## 4. 已做的改动

### 4.1 DTS —— `arch/arm64/boot/dts/exynos/exynos7420-zeroflte.dts`

在文件末尾（原 WiFi `#endif` 之后）新增一整段，用一个开关控制：

```dts
#define DSH_ENABLE_BT 0        /* ← 探测 0x114C0000 通过后改成 1 */
```

开关打开后会做这些事：

| 动作 | 内容 |
|---|---|
| alias | `serial0 = &serial_4;`（把 tty 编号钉成 0，见 §3.3） |
| CMU_AUD | `&{/soc@0/clock-controller@114c0000} { status = "okay"; }` |
| pinctrl | `&pinctrl_aud` 加 `bt_uart_bus`（`gpz1-3..0`，func 2，pull-up，与 vendor `uart_bt_active` 一致）<br>`&pinctrl_alive` 加 `bt_host_wake`（`gpa2-1`，func 0，无上下拉，与 vendor `:76` 一致） |
| BT_EN | `&gpf4` 里加 `gpio-hog`，pin 1 **output-high** |
| BT_WAKE | `&gpr3` 里加 `gpio-hog`，pin 4 **output-low** |
| UART | `&serial_4 { pinctrl-0 = <&bt_uart_bus &bt_host_wake>; status = "okay"; }` |

设计取舍说明：

- **BT_EN 用 `gpio-hog` 而不是 `regulator-fixed`**：ldisc 路径下没有任何驱动会
  `regulator_get()` 这个电源（`hci_bcm` 的供电/`shutdown-gpios` 只在 serdev 路径生效），
  一个没人消费的 regulator 不如 hog 直观。
  副作用是无法从用户态复位 BT —— 需要重启芯片时的做法见 §5.5。
- **`bt_host_wake` 只做 pin 配置，不请求中断**：ldisc 路径用不到 host-wake IRQ，
  `hci_bcm` 也不会去 request（`bcm->dev==NULL`）。等以后补 serdev 再打开。
- **引脚电气参数严格对齐 vendor**（`pin-function`/`pin-pud` 都照 `exynos7420-pinctrl.dtsi`
  抄），避免"自己发明配置"。

### 5.5 排障表

| 现象 | 原因 | 处理 |
|---|---|---|
| `/dev/ttySAC0` 不存在 | `serial@11460000` 没 probe：CMU_AUD 没开 / 时钟拿不到 | `dmesg \| grep -i "11460000\|samsung-uart\|clk"`；确认 p233；确认 DTB 里 `clock-controller@114c0000` 是 `okay` |
| 出现 `/dev/ttySAC4` 而不是 `ttySAC0` | 有人在 Kconfig 里把 `SERIAL_SAMSUNG_UARTS` 改成了 5，或 alias 被删 | 用实际节点名替换 `btattach` 的 `-B` 参数 |
| `btattach: Can't set line discipline` / `-EOPNOTSUPP` | 忘了 `-P bcm`，或流控被关掉（`-N`） | 不要加 `-N`；确认 `btattach ... -P bcm` |
| `hci0` 出现但 `hciconfig` 报 `UP` 不了 | 固件没下进去（`fw_load_done=false`），芯片还在 ROM 态 | 检查 §5.4 的 "file not found"；核对文件名 |
| 固件下到一半 timeout | 波特率/时钟不对（SCLK_UART 不是 24 MHz 也不是 117 MHz，或者是 0） | 见 §7 Plan B，用 fixed-clock 钉死 SCLK |
| 扫描不到设备 | 天线/共存问题，或 `BT_WAKE` 极性不对 | 见 §5.6 |
| 想强制给 BT 重新上电 | `gpio-hog` 一直拉着 `BT_EN`，用户态改不了 | 见 §5.6 |

### 5.6 需要"复位 BT"时怎么做

因为 `BT_EN` 被 gpio-hog 占着，用户态拿不到这条线。两个办法：

**办法 A（不改内核）**：把 DTS 里 `&gpf4 { bt-en-hog {...} }` 整段注释掉重新编译，然后：

```bash
GPIOCHIP=$(grep -l '"gpf4"' /sys/class/gpio/gpiochip*/label | head -1)
BASE=$(cat $(dirname "$GPIOCHIP")/base)
N=$((BASE + 1))                       # gpf4-1 = BT_EN
echo $N > /sys/class/gpio/export
echo out > /sys/class/gpio/gpio$N/direction
echo 0   > /sys/class/gpio/gpio$N/value; sleep 0.2
echo 1   > /sys/class/gpio/gpio$N/value; sleep 0.1
btattach -B /dev/ttySAC0 -P bcm -S 115200 &
```

**办法 B（推荐，长期方案）**：把 BT_EN 从 hog 改成 `regulator-fixed`，
以后由 serdev/hci_bcm 的 `shutdown-gpios` 管；这需要先给 `samsung_tty.c` 补 serdev 支持
（不在本次范围）。

## 6. 风险 / 阻塞项清单

| 级别 | 项 | 说明 | 解除条件 |
|---|---|---|---|
| **阻塞** | CMU_AUD `0x114C0000` 未实测 | 地址不在死区，但没 `mrd` 记录；开了会让内核读写它 | §5.0 探测通过 |
| 中 | SCLK_UART 实际频率未知 | 取决于 S-Boot 留下的 `DIV_AUD1`/`MUX_SEL_AUD`，以及 `fout_aud_pll` 是否可用（它挂在 **CMU_TOP0，而 CMU_TOP0 是实测死区、已被禁用**）。若 MUX 选到 `fout_aud_pll` 而该时钟没注册，`clk_get_rate()` 可能返回 0 | §7 Plan B |
| 中 | `bcm_uart_subver_table` 没有 BCM4358 | 固件只能用 `BCM.samsung,zeroflte.hcd` / `BCM.hcd` 这种兜底名 | 拿到 dmesg 里的 subver 后加一行表项 |
| 低 | `SERIAL_SAMSUNG_UARTS=4` 无 prompt | 已用 alias 绕过；将来若要 `ttySAC4` 才需要改 `drivers/tty/serial/Kconfig:254` 的 default | — |
| 低 | 无 BT_HOST_WAKE 中断 | ldisc 路径不 request IRQ ⇒ 没有"BT 唤醒主机"能力 | 补 serdev 后自然解决 |
| 低 | 固件要手工装 | 属于 rootfs 改动，本次**只准备脚本不执行** | Lead/用户执行 §5.2 |

**没有 TEE / secure 依赖**：vendor 的 BT 驱动 `bcm4358.c` 全文没有任何 SMC/secure 调用，
纯 GPIO + rfkill。这点比触摸简单得多。

## 7. Plan B：如果 CMU_AUD 走不通

如果 §5.0 探测发现 `0x114C0000` 读不通，还有一条**完全不碰 CMU_AUD** 的路：
把 `serial_4` 的时钟换成 `fixed-clock`，赌 S-Boot 已经把 UART4 的 pclk 门控留在开着的状态。

```dts
/ {
	bt_uart_pclk: clock-bt-uart-pclk {
		compatible = "fixed-clock";
		#clock-cells = <0>;
		clock-frequency = <66670000>;    /* aclk_aud/66MHz 量级，按需调 */
	};
	bt_uart_sclk: clock-bt-uart-sclk {
		compatible = "fixed-clock";
		#clock-cells = <0>;
		clock-frequency = <24000000>;    /* fin_pll；115200 完全够（div=12） */
	};
};

&serial_4 {
	clocks = <&bt_uart_pclk>, <&bt_uart_sclk>;
	clock-names = "uart", "clk_uart_baud0";
	/* 注意：这样 pclk 门控不会被驱动打开，只能依赖 S-Boot 的遗留状态 */
};
```

这条路和现有 DTS 里给 FSYS0/FSYS1 用 fixed-clock 替代 CMU_TOP1 的做法是同一个套路
（见 `exynos7420-zeroflte.dts` 里 `fsys1_aclk200` 那一堆）。
**但它比 Plan A 更赌**：CMU_AUD 不打开 ⇒ `PCLK_UART` 门控大概率是关的，
那样访问 `0x11460000` 同样会挂。所以**只作为探测失败后的备选**，不要先用它。
