## 0. TL;DR

| 键 | 硬件归属 | 接法 | 内核上报 |
|---|---|---|---|
| **BACK**（返回，右） | **Cypress CY8CMBR31x5 电容触摸键 IC** | i2c 0x20，SDA=`gpd1-2`，SCL=`gpd1-3`，IRQ=`gpa0-0` | `KEY_BACK` = 158 |
| **RECENT**（最近任务，左） | 同上 | 同上 | `KEY_APPSELECT` = 580（vendor 是 `KEY_RECENT`=254） |
| **HOME**（主页，物理键，指纹传感器在其下方） | SoC GPIO | `gpa0-5`，EINT5 | `KEY_HOMEPAGE` = 172 |
| VOL+ | SoC GPIO | `gpa0-2`，EINT2 | `KEY_VOLUMEUP` = 115 |
| VOL- | SoC GPIO | `gpa0-3`，EINT3 | `KEY_VOLUMEDOWN` = 114 |
| POWER | SoC GPIO | `gpa2-2`，EINT（muxed wakeup，共享 SPI16） | `KEY_POWER` = 116 |

**关键结论：BACK/RECENT 不是 stmfts 触摸屏上报的，也不是 Exynos 矩阵键盘。**
它们是挂在 **hsi2c3 上的独立 Cypress MBR 触摸键控制器**；vendor 的 STM 触摸驱动只有在
DTS 里有 `stm,num_touchkey` 属性时才会启用按键上报，而 zeroflte/CHN 的原厂 DTS 没有该属性。

因此本次改动 = ① gpio-keys（POWER/VOL/HOME，已由并行 agent 加好，本报告勘误其注释）
+ ② **新驱动 `cypress-mbr-touchkey`（BACK/RECENT）** + ③ DTS 里的 i2c-gpio 触摸键节点。

## 1. 硬件接法（含 vendor 证据）

### 1.1 物理键：POWER / VOL+ / VOL- / HOME —— gpio-keys

vendor `gpio_keys` 节点（`exynos7420-zero_common.dtsi:769-804`，CHN 原厂 DTB 反编译
`参考-zenlte主线移植/ctc_stock.dts:7746-7786`）：

```dts
gpio_keys {
    compatible = "gpio-keys";
    button@1 { label="KEY_POWER";      interrupts=<2 0 0>; interrupt-parent=<&gpa2>; linux,code=<116>; gpios=<&gpa2 2 0xf>; wakeup; };
    button@2 { label="KEY_VOLUMEDOWN"; interrupts=<3 0 0>; interrupt-parent=<&gpa0>; linux,code=<114>; gpios=<&gpa0 3 0xf>; };
    button@3 { label="KEY_VOLUMEUP";   interrupts=<2 0 0>; interrupt-parent=<&gpa0>; linux,code=<115>; gpios=<&gpa0 2 0xf>; };
    button@4 { label="KEY_HOMEPAGE";   interrupts=<5 0 0>; interrupt-parent=<&gpa0>; linux,code=<172>; gpios=<&gpa0 5 0xf>; wakeup; };
};
```

- gpa0/gpa2 都在 `pinctrl_alive`（`0x10580000`），**已实测可访问**（`0x10580000 = 0x00000000`，
  见 `05-专项/硬件实测-PERIC1与PMIC-20261018.md:45`）。
- gpa0 是"直接 EINT"bank（EINT0-7 → GIC SPI 0-7）；gpa2 是 muxed wakeup bank（共享 GIC SPI 16）。
- 主线的 `exynos_irq_request_resources()` 在 request_irq 时会自动把 pinmux 设成 EINT 功能
  （`drivers/pinctrl/samsung/pinctrl-exynos.c:150-176`），所以 gpio-keys 用 `gpios`（TM2 同款写法）
  即可，不需要 `interrupts` 属性。

### 1.2 电容键 BACK / RECENT —— Cypress CY8CMBR31x5（独立 I2C 器件）

CHN 原厂 DTB（`ctc_stock.dts:4857-4891`）：

```dts
hsi2c@14E70000 {                       /* SPI 460, 0x14E70000 */
    pinctrl-names = "default","on_i2c","off_i2c";
    pinctrl-0 = <&hs_i2c3_bus>;
    pinctrl-1 = <&cfg_i2c>;            /* gpd1-3/gpd1-2, func 3, pull none */
    pinctrl-2 = <&cfg_gpio>;
    touchkey@20 {
        pinctrl-names = "on_irq","off_irq","sub_det";
        pinctrl-0 = <&cfg_irq>;        /* gpa0-0, func 0xf, pull none */
        compatible = "cypress,cypress_touchkey";
        reg = <0x20>;
        interrupt-parent = <&gpa0>; interrupts = <0 0 0>;
        cypress,sda-gpio = <&gpd1 2 0>;
        cypress,scl-gpio = <&gpd1 3 0>;
        cypress,irq-gpio = <&gpa0 0 1>;
        cypress,sub-det  = <&gpa3 5 0>;
        cypress,ap-io-power = "true";
        cypress,ic-stabilizing-time = <150>;
        cypress,boot-on-ldo = "true";
        cypress,fw_path = "cypress/cypress_zerof.fw";
    };
};
```

同样的节点也在 `exynos7420-zeroflte_chn_01.dts:918-940`、`exynos7420-zeroflte_eur_open_00.dts:618-642`。
zeroflte 的 defconfig 打开了 **`CONFIG_KEYBOARD_CYPRESS_TOUCH_MBR31X5=y`**
（`arch/arm64/configs/exynos7420-zeroflte_defconfig:1828`），对应驱动就是
`drivers/input/keyboard/cypress_20075/cypress-touchkey.c`。

**协议（vendor 驱动 `cypress-touchkey.c:73-75, 1071-1089`）：**

```c
static int touchkey_keycode[] = { 0, KEY_RECENT, KEY_BACK };

keycode_data[1] = data[0] & 0x3;          /* bit[1:0] -> RECENT */
keycode_data[2] = (data[0] >> 2) & 0x3;   /* bit[3:2] -> BACK   */
input_report_key(..., touchkey_keycode[i], keycode_data[i] % 2);
```

即寄存器 **0x03**，每个键 2 bit：`0b01` = 按下、`0b10` = 抬起、`0b00` = 无事件。
中断是 **下降沿**（`cypress-touchkey.c:2609-2611`：`IRQF_TRIGGER_FALLING`）。
0x04 是固件版本（`touchkey_i2c_check()` 从 0x03 连续读 4 字节，`cypress-touchkey.c:200-222`）。

**供电：**

- 核心 3.3V = **S2MPS15 LDO21 `vtouch_3.3v`**（`touchkey_i2c.h:16`，`ctc_stock.dts:5082-5087` 标
  `regulator-boot-on`）。
- vendor 节点写了 `cypress,boot-on-ldo = "true"`，而驱动在 `boot_on_ldo` 为真时**根本不去 enable**
  该 LDO（`cypress-touchkey.c:2573`）⇒ **S-Boot 已经把它打开并保持**。
- IO 电源 `vtouch_1.8v` 由于 `cypress,ap-io-power = "true"`，vendor 驱动也不会去动
  （`cypress-touchkey.c:2331-2335`）⇒ 同样是 S-Boot 状态。

**关于 `sub-det`（gpa3-5）：** vendor 驱动 probe 时读它，若为 1 就判定"设备未连接"并拒绝 probe
（`cypress-touchkey.c:2592-2600`）。它只是模块/副板检测，不参与按键通信；主线驱动不需要读它。

### 1.3 为什么不是 stmfts / 不是 samsung-keypad

- **不是 stmfts**：vendor STM 驱动确实有触摸键支持（`fts_ts.c:88-98` 的
  `fts_touchkeys[] = {KEY_RECENT, KEY_BACK}`，事件 `EVENTID_MSKEY`），但只有在 DT 有
  **`stm,num_touchkey`** 时才置 `support_mskey = true`（`fts_ts.c:1749-1757`）。
  `ctc_stock.dts:5399-5416` 与所有 zeroflte DTS 的 `touchscreen@20` 节点**都没有**这个属性
  ⇒ STM 触摸屏不报按键。
  主线 stmfts 用 `touch-key-connected` 开关同一个功能（`drivers/input/touchscreen/stmfts.c:696-701`），
  本板**不能**加这个属性。
- **不是 Exynos 矩阵键盘**：vendor zero 系列 DTS 里没有任何 `keypad@` / `samsung-keypad` 节点，
  只有上面两处（gpio_keys + cypress touchkey）。
- **不是 PMIC onkey**：POWER 走 gpa2-2 GPIO（S2MPS15 的 PWRON 是硬件开机通路，软件也读同一 GPIO）。

## 3. 实际改动

### 3.1 新驱动 `drivers/input/keyboard/cypress-mbr-touchkey.c`

- compatible：`"cypress,mbr31x5-touchkey"`
- 读 `0x03`，每键 2 bit，`0b01` 按下 / `0b10` 抬起（`0b11` 按 vendor 语义当按下）
- 线程化 IRQ（`IRQF_ONESHOT` + DT 的 `IRQ_TYPE_EDGE_FALLING`），在进程上下文读 I2C
- 软件去重：同一状态不重复上报；`0b00` 不当作抬起
- probe 时先读一次 `0x03` 做存在性检查，再读 `0x04` 打印固件版本（便于上机排查）
- 支持 `linux,keycodes`（本板 `<KEY_APPSELECT KEY_BACK>`，对应 bit[1:0]=RECENT、bit[3:2]=BACK）
- 不做固件更新（固件在 IC 内部 flash，原厂只在版本不匹配时才走 ISP 重刷）
- suspend 时 disable_irq 并释放按住的键

> 为什么不用 mainline 现成的 `tm2-touchkey`：TM2 协议是
> `bits[2:0]=键号+1、bit3=press/release`（`tm2-touchkey.c:143-165`），与本板
> 的 2-bit/键 协议**不兼容**（同一个字节会被解成完全不同的键），因此单独写一个小驱动。

### 3.2 Kconfig / Makefile

```diff
+	tristate "Cypress CY8CMBR31x5 touchkey support"
+	depends on I2C
+

```

`CONFIG_KEYBOARD_GPIO=y`、`CONFIG_I2C_GPIO=y` 本来就有。

### 5.4 排查表

| 现象 | 检查 / 处理 |
|---|---|
| 没有 `mbr-touchkey`，dmesg 有 `touchkey controller does not respond` | 触摸键 IC 没上电或 I2C 不通：`i2cdetect -l` 找到新加的 i2c-gpio 总线，`i2cdetect -y N` 看 0x20；若 0x20 不存在，先怀疑 LDO21(`vtouch_3.3v`) 未开（vendor 依赖 boot-on，内核不动它） |
| 有 `mbr-touchkey` 但按键无反应 | `grep gpa0 /proc/interrupts` 看中断计数是否增长；不增长说明 IRQ 引脚/EINT 没通；增长说明 I2C 读失败（看 dmesg 的 ratelimited 错误） |
| BACK/RECENT 左右互换 | 把 DTS 改成 `linux,keycodes = <KEY_BACK KEY_APPSELECT>`（bit[1:0]/bit[3:2] 对调）后重编 |
| HOME 没反应 | `evtest` 选 gpio_keys 看有没有 `KEY_HOMEPAGE`；有事件说明内核 OK，是 GNOME 没绑定（见第 6 节） |
| POWER/VOL 没反应 | 看 `dmesg` 里 gpio_keys probe；`/sys/kernel/debug/gpio` 是否占用了 gpa2-2/gpa0-2/3 |
| 整机挂死 | 本方案没有访问任何未实测 MMIO，理论上不会；若挂死请保留 ramoops，并用 loader watchdog 复位 |

## 6. GNOME 侧行为（重要）

内核只负责把键值送进 `/dev/input/event*`；**GNOME 默认没有为这些键绑定动作**。
另外有一个 Wayland/X11 的硬限制：**xkb 的 keycode 上限是 255**（`/usr/share/X11/xkb/keycodes/evdev`
`maximum = 255`），Linux keycode 加 8 就是 xkb keycode，所以：

| 内核 keycode | xkb keycode | keysym | GNOME 可用性 |
|---|---|---|---|
| `KEY_BACK` 158 | 166 | `XF86Back` | 可绑定/部分应用直接支持 |
| `KEY_HOMEPAGE` 172 | 180 | `XF86HomePage` | 可绑定 |
| `KEY_APPSELECT` 580 | 588 > 255 | **无 keysym** | **GNOME 看不到，必须用 evdev 层重映射** |

有三种做法（任选）：

### 6.1 只配 HOME（零依赖，一条命令）

```sh
gsettings set org.gnome.shell.keybindings toggle-overview "['XF86HomePage']"
```
`toggle-overview` 在 GNOME 43（Debian 12）里就是"显示概览"（见 gnome-shell
`data/50-gnome-shell-system.xml`），效果等同按 Super。

### 6.2 推荐：evdev 层重映射（BACK/RECENT 都能用）

Debian 12 仓库自带 **`input-remapper`**（bookworm 1.5.0，X11/Wayland 都支持，带 GTK 界面）：

```sh
apt install input-remapper input-remapper-gtk
```

在它的界面里给 `mbr-touchkey` / `gpio_keys` 两个设备加映射（自动应用到开机/插拔），
在 **evdev 层**把：

| 物理键 | 映射成 | 效果 |
|---|---|---|
| BACK (`KEY_BACK`) | `Alt+Left` | Nautilus / GNOME Web / 大部分 GTK 应用返回 |
| HOME (`KEY_HOMEPAGE`) | `Super` | 打开概览（=回桌面/多任务） |
| RECENT (`KEY_APPSELECT`) | `Super+Tab`（或 `Super`） | 应用切换器 / 概览 |

备选是 `keyd`（Debian 12 仓库没有，需源码装：`git clone https://github.com/rvaiya/keyd && make && sudo make install`），
配置形态（`/etc/keyd/default.conf`，键名/语法以 keyd 文档为准）：

```ini
[ids]
*

[main]
back = alt+left
homepage = leftmeta
appselect = leftmeta+tab
```

> 备选：如果不想装任何用户态守护进程，可以把 DTS 里的 `KEY_APPSELECT` 换成
> `KEY_MENU`（139，xkb keysym = `XF86MenuKB`），然后用
> `gsettings set org.gnome.desktop.wm.keybindings switch-applications "['XF86MenuKB']"`
> 绑定最近任务键。代价是 Waydroid/Android 侧会把它当 MENU 而不是 APP_SWITCH。

### 6.3 为什么不用 vendor 的 `KEY_RECENT`(254)

254 在 mainline `input-event-codes.h` 里没有定义（249-255 未分配），且 xkb keycode 262 > 255，
GNOME 同样看不到。`KEY_APPSELECT`(580) 是 mainline/Android 对"最近任务"的标准码
（Android `AKEYCODE_APP_SWITCH`），evtest 也能显示名字，因此选它。

## 7. 风险 / 未决

1. **未上机**：所有结论来自 vendor 源码 + 已有实测的可访问性地图；p230 只做了编译验证。
2. **LDO21 状态**：主线不声明 `vtouch_3.3v`，依赖 S-Boot 的 boot-on 状态。未声明的 regulator
   constraints 为空，`regulator_late_cleanup()` 会跳过它（`drivers/regulator/core.c:6199-6225`），
   所以不会被内核关掉 —— 但**如果 S-Boot 本来就没开**，需要另行处理（这也是排查表第一项）。
3. **字段左右顺序**：vendor 数组是 `{RECENT, BACK}`，但"bit[1:0] 对应物理左键"是从驱动语义推断的，
   需用 evtest 确认；若反了改一行 DTS 即可。
4. **电源键唤醒**：`wakeup-source` 会走 gpa2 的 muxed wakeup EINT；当前系统基本不 suspend，
   若后续加 suspend 需要再验证。
5. **固件版本**：主线驱动不刷固件。如果以后遇到 IC 固件损坏（vendor 会 ISP 重刷
   `cypress/cypress_zerof.fw`），本驱动不提供该功能。
