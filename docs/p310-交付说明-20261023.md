## 一、本轮新增能力

### 1. 显示屏背光控制（从完全不可控 → 完全可控）

```sh
cat /sys/class/backlight/s6e3hf2/max_brightness   # 255
echo 40  > /sys/class/backlight/s6e3hf2/brightness   # 暗
echo 255 > /sys/class/backlight/s6e3hf2/brightness   # 最亮
```

原理：DECON 是 mainline 驱动的（i80 命令模式），但 **DSIM 和面板是 S-Boot 留下的孤儿** ——
`exynos7.dtsi` 里 `dsi` 节点数 = 0，`samsung-dsim` 从未 probe。
所以背光由 `exynos7_drm_decon.c` 直接往 **DSIM 的 SFR FIFO** 写 DCS 命令实现：

| 命令 | 作用 |
|---|---|
| `0x28` | display off（熄屏时面板停止发光）|
| `0x29` | display on（唤醒）|
| `0x53 0x20` + `0x51 N` | 设亮度 |

**刻意不发 `0x10`(sleep in)** —— 进 sleep 要完整初始化序列才能回来，
而那份序列在 S-Boot 手里，mainline 没有。

### 2. GPU DVFS（真实频率 + 可升降）

```sh
cat /sys/kernel/debug/panfrost-g3d/state
#   ramp=on strategy=0 pll=266000000 core=266000000
#   mux_parent_rate=266000000 safe=24000000

echo 700000000 > /sys/kernel/debug/panfrost-g3d/rate   # 升频（看视频）
echo 266000000 > /sys/kernel/debug/panfrost-g3d/rate   # 回默认
```

**重大发现**：之前 DTS 里 `fout_g3d_pll = FRATE(700000000)` 是**硬编码常量**，
实测 CMU_G3D PLL `CON0=0xa0850621` → M=133 P=6 S=1 = **266MHz**
（与 vendor `table_g3d[]` 最低档一致）。所以 GPU 从来没跑过 700MHz。

变频**不能**用 aclk 分频器（CMU_G3D 里没有，`clk-exynos7.c` 里的
`div_aclk_g3d`/`div_pclk_g3d` 是本项目凭空造的），只能改 PLL，
安全序列（照 vendor `gpu_exynos7420.c:298-352`）：

```
clk_set_parent(mout_g3d, fin_pll)        ← GPU 退回 24MHz 常稳时钟
clk_set_rate(fout_g3d_pll, target)       ← 此时改 PLL 对 GPU 不可见
udelay(50)                               ← 必须 >37.5us（P=6 × 150 × 24MHz）
clk_set_parent(mout_g3d, fout_g3d_pll)   ← 切回
```

**注意**：`samsung_pll35xx_set_rate()` 的 LOCK 轮询会**假通过** ——
写 PMS 前 LOCK 位已经是 1，第一次读就返回。所以必须自己 `udelay`。

## 二、功耗实测（中位数，PC USB 500mA 输入下）

| 状态 | 电流 |
|---|---|
| brightness=160（默认）| -608 mA |
| brightness=255 | -597 mA |
| **brightness=1** | **-392 mA** |
| **DPMS Off（熄屏）** | **-356 mA** |
| 唤醒后 | -401 mA |

**⇒ 熄屏省 ~250mA，是本轮最大的单项收益**

历史对比：刷 p310 之前熄屏是 -484 ~ -604mA。

## 三、踩过的三个坑（务必记住）

### 坑 1：decon.c 缺前向声明
`dsh_dsim_display()` / `dsh_dsim_set_level()` 定义在文件后半部分（~1087/1120 行），
但 `decon_atomic_enable()`（~820 行）就调用 → `implicit declaration` + `conflicting types`。
修复：在 `struct decon_context` 之后（~180 行）加两个 `static` 声明。

### 坑 2：`build_mainline.sh` 不编模块
`CONFIG_DRM_EXYNOS=m` → 背光代码在 `exynosdrm.ko` 里。
只跑 `./build_mainline.sh pNNN` 刷了镜像也没有背光，必须：
```sh
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc) modules
```

### 坑 3：模块有三份副本
```
/usr/lib/modules/<ver>/drivers/gpu/drm/exynos/exynosdrm.ko   ← modinfo 指向这份
/usr/lib/modules/<ver>/extra/exynosdrm.ko
/usr/lib/modules/<ver>/kernel/drivers/gpu/drm/exynos/exynosdrm.ko
```
只更新 `kernel/` 那份**不生效**。三份都 `cp` + `depmod -a`。

## 四、回滚

| 想回滚什么 | 怎么做 |
|---|---|
| 背光 | cmdline 加 `exynosdrm.backlight=0`（完全不碰 DSIM，与打补丁前一致）|
| 背光（只读诊断）| `exynosdrm.bl_dump=1`（只读一次 DSIM STATUS，不注册 backlight）|
| 亮度 | `exynosdrm.bl_level=N`（默认 160）|
| GPU 频率 | `echo 266000000 > /sys/kernel/debug/panfrost-g3d/rate` |
| GPU devfreq | DTS 注释掉 `operating-points-v2`（debugfs 仍可用）|
| 整个镜像 | 刷回 `out/p261-padded.img`（sha1 240c5a41）|
