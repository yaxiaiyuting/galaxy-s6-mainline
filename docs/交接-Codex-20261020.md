## 当前未解决（接手重点）

### ① GNOME 交互卡顿（用户主诉：触摸时延迟特别高）
**已排除**：
- CPU 不是瓶颈（load 0.37 / 8 核，89% idle）
- 触摸屏硬件正常：`stmfts` @ `14e10000.i2c`(i2c-2) 400kHz，独立 IRQ GIC_SPI 462
- GPU 无新 fault（`js fault` 只有 1 条旧的）

**根因假设（高置信）**：
`simpledrm` 的 framebuffer 是**固定内存区**，无法 import DMA-BUF。
⇒ panfrost 渲染完必须 **CPU 拷贝 14MB/帧** 到 simpledrm 的 fb → 高延迟
⇒ 换 llvmpipe 也一样慢（CPU 全量渲染 3.7M 像素）

**解决方向**：
- **A（根治）**：实现 `exynos_drm`（DEcon + DSI）作为真正显示驱动
  ⇒ panfrost 渲染到 DMA-BUF，DEcon 直接扫描输出 ⇒ **零拷贝**
  - 树里已有 decon/dsi 节点（被 `DSH_ENABLE_DISP_IOMMU=0` 关着）
  - 风险：`0x13AD0000`(CMU_DISP)、`0x13930000`(DECON) 未实测，可能 AXI 挂死
  - **必须先探测**：loader `mrd 0x13AD0000` / `mrd 0x13930000` + `watchdog arm`
- **B（快速改善）**：换轻量桌面（XFCE/LXQt），渲染负载大幅下降
- **C（临时）**：`PAN_MESA_DEBUG=noafbc,nocrc` 已有，但解决不了呈现带宽

### ② GNOME 缩放 2x 未生效
已写入：
- `/root/.config/monitors.xml`（scale=2, connector=Unknown-1, 1440x2560@60.000）
- `/var/lib/gdm3/.config/monitors.xml`（同内容，chown Debian-gdm）

**未生效可能原因**：
- `<rate>60.000</rate>` 与实际 vrefresh 不匹配 → mutter 忽略该 monitor 配置
- 需要确认实际 vrefresh：`/sys/class/drm/card0-Unknown-1/modes`
- 或 connector 名/vendor/product/serial 三元组不匹配
- **调试**：`journalctl -b | grep -iE 'monitor.*config|scale|logical'`
- **备选**：`gsettings set org.gnome.desktop.interface text-scaling-factor 2.0`（需在用户 session 里，用 `runuser -u Debian-gdm -- env XDG_RUNTIME_DIR=/run/user/106 DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/106/bus ...`）

## 关键调试手段

### 宿主机 USB 网络（每次手机重启后要重配）
```bash
IF=$(ls /sys/class/net/ | grep -vE "cvd|virbr|xray|singbox|waydroid|^lo$|eno1|wlan0" | head -1)
sudo ip link set $IF down; sleep 1
sudo ip addr flush dev $IF
sudo ip addr add 192.168.42.1/24 dev $IF
sudo ip link set $IF up          # 必须 down/up 一次 carrier 才起来
sudo iptables -t nat -A POSTROUTING -s 192.168.42.0/24 -o wlan0 -j MASQUERADE
sudo sysctl -w net.ipv4.ip_forward=1
sudo ufw allow in on $IF
```
**注意**：宿主机默认路由是 `default dev xray_tun metric 1`，
`awk '{print $5}'` 会误取到 "1"，**必须手写 `wlan0`**。

### 通过 USB 网络执行手机命令（输出回传）
```bash
# 手机端把输出发到宿主机 TCP
sudo timeout 90 python3 - <<'PY'
... (见 /tmp/pq.py，如果还在)
PY
```
核心原理：`nohup bash -c '{ CMD ; } > /dev/tcp/192.168.42.1/PORT 2>&1' &`

### 直接串口 shell（/dev/ttyACM0，115200）
- 有 `root@g9209:~#` 提示符时可直接执行
- 输出被日志淹没时：先 `echo 3 > /proc/sys/kernel/printk`
- **远程"看"屏幕**：`gzip -c /dev/fb0 > /dev/tcp/192.168.42.1/PORT`，
  宿主机侧解压后按 1440×2560 ARGB8888 转 PNG
  ⚠️ **注意**：mutter 用 atomic modeset 时 `/dev/fb0` 可能不是真实画面，仅供参考

### 崩溃取证（loader 的 prevlog）
手机挂死被看门狗复位后，loader 里发 `prevlog` 可打印**崩溃内核最后 16KB console**。
`[diagrec]` 记录里有 `text:` 字段（如 `Oops: Fatal exception in interrupt`）。
⚠️ `initcall=`/`caller=` 字段可能是误导（只是最后启动的 initcall、panic 返回地址）。

## 危险的地址（绝对不要碰）
**AXI 静默挂死（无 oops、只能看门狗复位）**：
`0x14C00000 ~ 0x14CE0000` 整段（含 `0x14C80000`/`0x14C90000`/`0x14CE0000`）
**未实测、需探测**：`0x10570000`(CMU_TOPC)、`0x10570A04`、`0x13AD0000`(CMU_DISP)、`0x13930000`(DECON)

## 刷机流程
```bash
# 1. loader 里：reboot recovery
sudo ./g9209-console.py --recover --timeout 30 "reboot recovery"
# 2. TWRP 里：
adb push out/pNNN-padded.img /tmp/
adb shell 'dd if=/tmp/pNNN-padded.img of=/dev/block/by-name/BOOT bs=1048576'
# 3. 校验 sha1 在镜像偏移 576 处 20 字节
adb shell 'dd if=/dev/block/by-name/BOOT bs=1 skip=576 count=20'
# 4. adb reboot → 回到 loader → 发 boot
setcmd          # 清空之前残留的 setcmd
watchdog arm
boot
```
**⚠️ 只刷 BOOT 分区**，绝不要碰 BOOTLOADER/PIT/EFS/PARAM。
