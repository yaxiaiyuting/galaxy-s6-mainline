## 0. TL;DR（先看这个）

1. **p207/p209 的 26 秒崩溃不是 PCIe/WiFi，而是 panfrost(GPU) 的异步 SError**：gnome-shell 关闭 Panfrost perfcnt fd → runtime resume → `panfrost_gpu_soft_reset()` 访问未真正上电的 GPU 寄存器（0x14AC0000 块）→ `Asynchronous SError Interrupt` → panic。完整 call trace 见 §1，**已用 ramoops `prevlog` 抓到全文**（不再需要长串口抓取）。
2. **WiFi 驱动本身已经通了，且已实测关联成功**：p207（完整 PHY、无 skip）启动后 brcmfmac 成功 probe，`wlan0 → wlp1s0`，MAC `<PHONE_MAC>`；在 p209（p207 + GPU disabled，稳定版）的串口 shell 里用 `wpa_supplicant` 已**成功关联 `<YOUR_SSID>`（5GHz/5220MHz/WPA2-PSK，-53dBm，wpa_state=COMPLETED）**，见 §2.3。说明 PHY/SYSREG/PCS 配置、LTSSM、link up、固件下载、MSI 中断、DMA 全部工作。**不需要再改 PCIe 驱动，也不需要"只启用 SYSREG / 只启用 PHY PCS"的镜像**。

5. **WiFi 只剩最后一步 `dhclient wlp1s0`（拿 IP）**：`wpasupplicant/iw/rfkill` 已装好、`/etc/wpa_supplicant/wpa_supplicant.conf` 已持久化、AP 已关联；dhclient 正要跑时手机电池耗尽。下次开机按 §4.2 / §5.5 约 1 分钟补齐，并可用 §5.4 做成开机自动连接。

### 1.2 为什么是"异步 SError"而不是普通 Oops

`arch/arm64/kernel/traps.c` 的 `do_serror()` → `arm64_serror_panic()`：内核态收到异步 SError 时打印
`SError Interrupt on CPUx, code ... -- SError` 后直接 `panic("Asynchronous SError Interrupt")`。
本板"未上电 IP 访问"有两种表现：**没有响应 → AXI 静默挂死**（拿不到 oops）；**返回错误响应 → SError**（本次）。
本次是 GPU 电源域在 runtime PM 里"声称上电但实际没上电/没解隔离"，访问立即得到错误响应。

### 1.3 与 PCIe 无关的排除证据

1. **p207 完整启动日志里 WiFi 已成功**：`brcmfmac 0000:01:00.0 wlp1s0: renamed from wlan0`（13.557s），
   MAC `<PHONE_MAC>`，uevent 路径 `/devices/platform/157b0000.pcie/pci0000:00/0000:00:00.0/0000:01:00.0`
   ⇒ PCIe host 驱动 probe 完成、链路 up、BCM4358 固件加载成功。若 PHY 配置有致命问题，不可能走到这一步。
2. **驱动里没有 `.sync_state` 回调**：`exynos7420_pcie_host_ops` 只有 `.host_init`；DWC 框架 `dw_pcie_host_ops` 也没有。
3. **IRQ handler 无 NULL 解引用**：`pci-exynos7420.c:425-448`，只读 ELBI `0x000/0x004/0x008` 并回写清中断，
   再 `if (pp->has_msi_ctrl && pp->irq_domain) dw_handle_msi_irq(pp)`；`ep/pp/elbi_base` 都在 probe 里初始化。
4. **两个"可疑地址"都在 probe 同步路径，且 p207 已证明安全**：
   - `0x1005265C`（SYSREG，"block"）：`exynos7420_pcie_phy_config()`（`pci-exynos7420.c:371`）内 **行 378-385** 读改写 refclk 选择位，**行 409-417** CMN_RST 20µs 脉冲；
   - `0x156F00E4`（PHY PCS，"phy_pcs"）：**行 406-407** 一次 `writel(0x2, ep->phy_pcs_base)`；
   - 二者靠 DTS 属性 `samsung,skip-phy-sysreg` / `samsung,skip-phy-pcs` 跳过（`pci-exynos7420.c:591-594`），
     **p207 DTS 没有这两个属性、系统正常启动并有 WiFi** ⇒ 两个地址都可安全访问，**skip 属性可以永久删除**（当前树已删除，见 p209）。
5. **`dsh_diag` 记录字段的真实含义**：
   - `initcall=ffffffc08115d140`（=`of_platform_sync_state_init+0`）来自 `init/main.c:1289`
     `dsh_mark((unsigned long)fn)` —— 记录"最后开始执行的 initcall"，**不是崩溃位置**；
   - `caller=ffffffc0800450f4` 用 objdump 验证 = `nmi_panic+0x68`（`panic()` 返回地址），
     `fmt` 指向 panic 格式串，`text: Asynchronous SError Interrupt` 是 panic 消息。
   - 因此旧结论"崩溃在 deferred probe / sync_state"**不成立**。

## 3. 修复方案

### 3.0 实际采用的方案（已验证）：p209 = p207 + GPU disabled

最终采用 **display-fixer 的"路径 A"**：`&gpu { status = "disabled"; }`，让 GNOME 走
simpledrm + llvmpipe 软件渲染，panfrost 不绑定 → 不再有 GPU runtime resume → **26s SError 消失**。
好处：**GNOME 能上屏 + WiFi 能同时验证**，不用改内核代码、不用改 `.config`、不碰任何未实测寄存器。

- 已落地镜像：**p209**（kernel #242，2026-10-19 04:33:06，DTB sha 见 `out/p209-manifest.json`），
  `gpu@14ac0000 { status = "disabled"; }`，pcie 完整 PHY、无 skip。
- 实测：稳定运行 >4 分钟（直到电池耗尽），`Reached target graphical.target`、gdm3 正常、
  `wlp1s0` 存在并可关联 AP（§2.3/§2.4）✅

### 3.1 方案 A（历史备选，已不需要）：多用户模式启动，绕过 GNOME/panfrost

> 在 p209 验证成功之前准备的"不碰 GPU"方案；现在 p209 已同时满足 GNOME + WiFi，**不再需要**。
> 保留记录，供将来若 p209 不可用时（例如需要 GPU 加速但电源域未修好）快速绕过。

两条实现路径，任选其一：

**A1（最快，不重建、不刷机）— 用 loader `setcmd` 改 Debian 的 default target。**
手机在 loader 时串口发送（整行，≤1023 字节）：

```
setcmd N=0; while [ ! -b /dev/sda20 ] && [ $N -lt 60 ]; do N=$((N+1)); sleep 1; done; mkdir -p /mnt; mount -t ext4 -o rw /dev/sda20 /mnt && mkdir -p /mnt/etc/systemd/system && ln -sf /usr/lib/systemd/system/multi-user.target /mnt/etc/systemd/system/default.target && echo DSH-PATCH-OK >/dev/ttyGS0; sync; umount /mnt
```

然后 `boot`。原理（源码依据：`uniLoader/blob/ramdisk` 内 `/etc/rc`）：
- `/etc/rc` 读 `/sys/firmware/devicetree/base/chosen/g9209,command`；
- 命令非空且不含 `norootfs/bootdebian` ⇒ `DSH_SWITCH=0`，**不切根到 Debian**；
- 继续走诊断流程，最后 `/bin/sh -c "$CMD"` 执行上面的命令（挂 UFS、改符号链接、sync、umount）；
- 任务结束后 PID1 通过 DT syscon-reboot（PMU `0x105c0400=1`）自动重启回 loader（p107 已验证的行为，
  见《主线移植-p107后续验证.md》§"带非空 setcmd 的任务完成后，PID1 调用标准 reboot …返回 loader"）。
- **这一 boot 全程不进 Debian、不碰 GPU，所以不会 26s 崩。**
- 串口预期输出：`DSH-PATCH-OK`、`G9209 COMMAND END status=0`，然后重启回 loader。

回到 loader 后：`setcmd`（不带参数清空残留）→ `boot` ⇒ Debian 以 multi-user.target 启动，无 gdm3/gnome-shell
⇒ 不触发 panfrost ⇒ **系统稳定，可以配置 WiFi**。

**A2（备选，需构建 1 次）— 改 loader bootargs：**
`uniLoader/main/diag.c:59-62` 的 `args[]` 末尾追加 ` systemd.unit=multi-user.target`，`./build_mainline.sh pNNN`。
（注意：改 `uniLoader/` 不在我的允许范围，由 Lead 执行。）

### 3.2 方案 B（产品级，GNOME 硬件加速 + WiFi 共存）：由 display-fixer 修 GPU 电源域

**status：p210 候选方案已在准备（display-fixer）。** 两条路：
1. **近路（p210，纯 DTS）**：`&gpu { status = "okay"; /delete-property/ power-domains; };`
   ⇒ genpd 永不断电，panfrost suspend/resume 只操作 GPU 自身电源寄存器，不再经过没实现的 pd_g3d 上电序列；

## 8. 附录：本次串口联调经验（下次省时间）

### 8.1 噪声控制（重要）

当前 bootargs 带 `loglevel=8 systemd.log_level=debug systemd.log_target=kmsg`，systemd/udev 的 debug
日志会疯狂刷 ttyGS0，导致：
- 串口输出把命令回显/结果淹没；
- 长命令（apt/dhclient/journalctl）输出过大时，串口表现像"卡住"。

**进 shell 第一件事**（只影响 console 输出，不影响 dmesg 缓冲）：
```sh
echo 3 > /proc/sys/kernel/printk       # 降噪；调试完可 echo 8 恢复
```
另外：`systemctl restart gdm3`、`journalctl -b`、`apt-get update` 这类命令务必
`> /tmp/xxx.log 2>&1 &` 后台跑，再 `tail` 轮询，不要在串口前台直接输出。

### 8.2 串口命令交互小工具（本次用的方法）

```python
# 115200 8N1 raw；每发一条命令追加唯一 marker，读到 marker 即认为命令完成
os.write(fd, f"{cmd}; echo __DSH_END_{i}__\r\n".encode())
# 读循环: select + os.read(fd, 65536)，直到 marker 出现（超时建议 30~300s 按命令定）
```
要点：
- 打开 `/dev/ttyACM*` 后要 `tcsetattr` 成 raw（`VMIN=VTIME=0`、非阻塞）；
- 只读抓日志时**不要写任何字节**；要发命令时注意 `TIOCEXCL`（其他 agent 会抢）；
- 手机重启/掉 USB 后 ACM 节点会重建，需要重新 open；
- loader 阶段（1209:316d）主机**刚连上时**会自动重放完整 dsh_log，之后新内容可用 `log` 命令强制重放。

### 8.3 关键路径备忘

| 用途 | 位置 |
|---|---|
| loader 控制台 | USB `1209:316d`，`/dev/ttyACM*` |
| Debian 控制台 | USB Gadget `1209:9210`（`console=ttyGS0`，autologin root；密码 root/root） |
| 宿主机→手机网络 | ECM `enp6s0f4u2i2` 192.168.42.1/24；手机 `usb0` 192.168.42.2/24 |
| loader 崩溃取证 | `prevlog`（ramoops console 最后 16KB）→ 搜 `SError Interrupt`/`Kernel panic` |
| dsh 诊断记录 | 主机连上 loader 自动重放 `[diagrec] previous build=… stage=… caller=… text:` |
| GPU 状态（p209） | 只有 `/sys/class/drm/card0`（simpledrm）；无 `card1`（panfrost） |
| WiFi 接口 | `wlp1s0`（不是 wlan0） |
