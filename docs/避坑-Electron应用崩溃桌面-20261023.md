# 避坑：Electron 应用（SPlayer）导致整个 GNOME 会话崩溃 / 系统重启

日期：2026-10-23
影响：SPlayer 3.1.1（Electron）on SM-G9209 + Exynos 7420 exynos-drm

---

## 现象

从 dock 点击 SPlayer → **整个桌面崩溃**，VT 跳到 tty1（GDM greeter），
屏幕上所有窗口消失。严重时**整机重启**。

journalctl 证据（上一轮启动的尾部）：

```
22:03:35 gnome-shell[159328]: meta_later_add: assertion 'display' failed
22:03:35 gnome-shell[159328]: meta_later_remove: assertion 'display' failed
22:03:35 gnome-shell[159328]: Could not release device '/dev/input/event0':
                             The name :1.8 was not provided by any .service files
22:03:39 NetworkManager[347]: manager: NetworkManager state is now DISCONNECTED
22:03:39 NetworkManager[347]: exiting (success)
22:03:44 wpa_supplicant: 强制杀掉（busy loop）
22:05:05 app-splayer-162744.scope: Stopping timed out. Killing.
22:05:05 systemd-journald[190]: Journal stopped
```

Electron 侧日志：

```
Failed to create scanout resource
DRM_IOCTL_MODE_CREATE_DUMB failed: 权限不够           ← EPERM
Cannot create bo with format=RGBA_8888 and usage=Scanout|Rendering|Texturing
```

## 根因链

1. **Electron 用 `--ozone-platform=wayland`** 启动，并自动选
   `--render-node-override=/dev/dri/renderD129`（exynos-drm 的 render node）。
2. 它要创建 scanout/GBM buffer，走 `DRM_IOCTL_MODE_CREATE_DUMB`。
3. **`DRM_IOCTL_MODE_CREATE_DUMB` 是 modeset 类 ioctl**
   （`DRM_IOCTL_DEF(DRM_IOCTL_MODE_CREATE_DUMB, drm_mode_create_dumb_ioctl, DRM_AUTH|DRM_RENDER_ALLOW)` 里
   的 `DRM_AUTH` 语义 + GEM dumb 属于 KMS 路径），
   **在 render node 上调用会被 `drm_ioctl_permit()` 拒绝 → 返回 EPERM。**
4. Electron 的 GPU 进程对这个失败**反复重试**（日志里刷屏），
   同时可能还在反复尝试 EGL/GBM 上下文初始化。
5. 这种异常路径把 **mutter 的 `MetaDisplay` 状态搞坏了**
   → `meta_later_add: assertion 'display' failed`（display 对象已释放还在用）
   → gnome-shell 崩溃 → gnome-session 退出 → GDM 回落 greeter。
6. 有时崩溃发生在系统关停路径上，会连带 NetworkManager/wpa_supplicant
   卡死（brcmfmac 的 `msgbuf_query_dcmd` 超时），最终**整机重启**。

## 修复

**让 Electron 走 X11（Xwayland），完全不碰 DRM。**

```ini
# /usr/share/applications/SPlayer.desktop
Exec=/opt/SPlayer/SPlayer --no-sandbox --disable-gpu \
     --disable-gpu-compositing --use-gl=swiftshader \
     --disable-dev-shm-usage --disable-features=Vulkan,UseSkiaRenderer %U
```

关键是**去掉 `--ozone-platform=wayland`**：
- 有 `DISPLAY`（GNOME 会话里有）时 Electron 会选 X11 ozone
- 缓冲由 **Xwayland** 通过 `wl_shm` 管理，**不再走 DRM dumb buffer**
- 加上 `--disable-gpu*` + `--use-gl=swiftshader` 走纯软件渲染

验证：

```sh
# 1. 确认 Xwayland 在跑
pgrep -c Xwayland            # 应该是 1

# 2. 确认 X11 能连（需要会话的 XAUTHORITY）
export DISPLAY=:0
export XAUTHORITY=/run/user/0/.mutter-Xwaylandauth.XXXXXX
xdpyinfo | head -3           # 应输出 X.Org version

# 3. 启动后检查
pgrep -fc SPlayer            # 6 左右
pgrep -c gnome-shell         # 仍为 1-2，VT 仍是 tty2
```

实测：**SPlayer 6 个进程运行，gnome-shell 存活，VT 保持 tty2**。

## 通用教训（适用于任何 Electron/Chromium 应用）

在 **Exynos 7420 的 exynos-drm**（没有 dumb buffer / GBM 支持）上：

| 做法 | 结果 |
|---|---|
| `--ozone-platform=wayland` | ✗ Electron 走 GBM → CREATE_DUMB EPERM → **崩桌面** |
| 默认（有 DISPLAY，走 X11） | ✓ Xwayland 管缓冲 |
| `--disable-gpu` 但仍 wayland ozone | ✗ 仍会初始化 GPU 进程碰 GBM |
| X11 + `--disable-gpu --use-gl=swiftshader` | ✓ 稳定，但纯 CPU 渲染较慢 |

**对其他 Electron 应用（VS Code、Discord 等）同样适用：**
**在这台设备上不要用 wayland ozone，让它们走 Xwayland。**

## 残留问题

- `tools.node` 需要 GLIBC 2.38，Debian 12 只有 2.36 → 非致命，Electron 回退
- 网易云音乐 API 有 DNS 失败（`EAI_AGAIN`），界面内容可能加载不出
- 纯软件渲染在 1440x2560 上会卡
