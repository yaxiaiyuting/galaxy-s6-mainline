# Exynos7420 GPU 加速修复报告（p211：GENPD_FLAG_ALWAYS_ON）

> 设备：Samsung SM-G9209（zeroflte，Exynos7420，Mali-T760 MP8）
> 内核：`/home/duanjb666/linux7420/linux-6.6/`（Linux 6.6.0-dirty）
> 日期：2026-10-20
> 目标：修好 panfrost 在 runtime suspend/resume 时的 SError panic，恢复 GPU 硬件加速
> 结论：**采用 GENPD_FLAG_ALWAYS_ON（p211）—— 域永不断电、电源序列一次都不执行，从机制上消除 SError 路径**。

## 0. TL;DR（先看这个）

| 问题 | 结论 |
|---|---|
| p207 为什么崩？ | panfrost job 结束 → 50ms autosuspend → **genpd 把 pd_g3d 断电**（写 `0x105C4100=0`，通用 5433 配置无 vendor 上电序列）→ gnome-shell 关 perfcnt fd 触发 runtime resume → genpd "名义上电" 只写 `0xf` → GPU 实际不可访问 → `panfrost_gpu_soft_reset()` 读 `0x14AC0000` → **Asynchronous SError → panic** |
| 最干净的解 | **`GENPD_FLAG_ALWAYS_ON`**：genpd 永不 power-off → `genpd_power_on()` 因 `status==ON` 直接返回 → **不完整的 `exynos_pd_power_on()` 一次都不执行** → 域保持 bootloader 的上电状态（p207 证明该状态下 GPU 可访问）→ panfrost 的 suspend/resume 只操作 GPU 内部 power 寄存器（上游标准路径）→ 不再 SError |
| 可行性 | ✅ 已逐行核对 `drivers/base/power/domain.c`：`genpd_power_off()` 对 always-on 域返回 `-EBUSY`（调用点忽略返回值，不影响 suspend）；`genpd_power_on()` 在 `status==ON` 时直接返回；`pm_genpd_init()` 不清 flags（但必须在 init **之后**置 flag，见 §3.2） |
| 改动量 | **~20 行**：`exynos-pm-domains.c`（config 字段 + g3d cfg + of_match + probe 置 flag）+ `exynos7.dtsi` 1 行（pd_g3d compatible） |
| 与 p210 的关系 | **互斥的二选一**。p210 = `/delete-property/ power-domains` + `pd_ignore_unused`；p211 = 保留 power-domains + ALWAYS_ON。p211 不依赖 cmdline、不破坏 device-genpd 拓扑，更稳（§2.3） |
| 影响范围 | 只影响 `pd_g3d`（新 compatible 只写在这一个节点），**其他电源域零影响** |
| vendor 完整序列 | 短期**不可行**：需要 RMW `CMU_TOPC + 0xA04 = 0x10570A04`，而 CMU_TOPC(0x10570000) 在本板是"读即挂"嫌疑区 → 需 Lead loader 探测（§7）。ALWAYS_ON 是当前唯一低风险解 |
| `.config` | **不需要改**（`CONFIG_DRM_PANFROST=y`、`CONFIG_PM_GENERIC_DOMAINS=y` 已满足；IOMMU 与 GPU 无关） |

## 1. 崩溃机制（逐层证据）

### 1.1 调用链（p207 Oops 复述）

```
gnome-shell 关闭 panfrost perfcnt fd
  → drm_release → panfrost_postclose → panfrost_perfcnt_fini
  → panfrost_perfcnt_disable → pm_runtime_get_sync()   ← 触发 runtime resume
  → rpm_resume → genpd_runtime_resume
      → genpd_power_on(): 写 pd_g3d LOCAL_PWR_CFG = 0xf（通用 5433 配置）
      → __genpd_runtime_resume → pm_generic_runtime_resume
  → panfrost_device_resume() → panfrost_device_reset()
  → panfrost_gpu_soft_reset() → 读 GPU 寄存器（0x14AC0000 区）
  → SError Interrupt（AXI 访问未上电/未就绪 IP 块，本板特性）
```

### 1.2 为什么会有"断电"这一步

| 代码 | 行为 |
|---|---|
| `panfrost_drv.c:590-594` | probe 末尾 `pm_runtime_set_active()` + `pm_runtime_enable()` + **autosuspend 50ms** |
| `panfrost_job.c:197` | 每次 job 提交 `pm_runtime_get_sync()` |
| `panfrost_job.c:445/464` | job 完成 `pm_runtime_put_autosuspend()` |
| `panfrost_device.c:414-425` | runtime suspend：job idle 检查 → `panfrost_devfreq_suspend()` → `panfrost_gpu_power_off()`（只关 **GPU 内部** power 寄存器） |
| `drivers/base/power/domain.c:929` `genpd_runtime_suspend()` | 设备 suspend 后调用 `genpd_power_off()` → **写 PMU `0x105C4100 = 0`，整个 G3D 域断电** |
| `drivers/base/power/domain.c:1005` `genpd_runtime_resume()` | 设备 resume 前调用 `genpd_power_on()` → 用本驱动 `exynos_pd_power_on()` 上电 |

### 1.3 为什么"上电"是假的

mainline 给 G3D 用的是 `samsung,exynos5433-pd` 的通用配置
（`drivers/pmdomain/samsung/exynos-pm-domains.c` 的 `exynos5433_cfg`：只有 `local_pwr_cfg = 0xf`），
上电/断电只做 `writel(0xf / 0, 0x105C4100)` + 等 status。

而 vendor 的 `pd-g3d` 上电序列（`los20/.../arch/arm64/mach-exynos/pm_domains-exynos7420-cal.h`）还需要：

| 类别 | 内容 | 位置 |
|---|---|---|
| top clock | `ENABLE_SCLK_TOPC1` bit9（top→local 时钟门控） | `0x10570A04`（CMU_TOPC `0x10570000` + 0xA04） |
| local clock | `ENABLE_ACLK_G3D` bit1 | `0x14AA0800` |
| PMU SYS_PWR ×7 | CLKRUN `0x1460`b0 / CLKSTOP `0x14A0`b0 / DISABLE_PLL `0x14E0`b0 / RESET_LOGIC `0x1520`b0 / MEMORY `0x1560`b1、b0 / RESET_CMU `0x15A0`b0 | PMU `0x105C0000` 区 |
| pd-option | `0x1101` 写入 `LOCAL_PWR_OPTION`（base+0x8） | `0x105C4108` |
| save/restore | `DIV_G3D/MUX_SEL_G3D/ENABLE_ACLK_G3D/ENABLE_PCLK_G3D/ENABLE_SCLK_G3D` + GPU 自身 `G3D_LOCK/CON/CON1/CON2` | CMU_G3D + GPU |
| 其它 | TMU 降噪、BUCK6EN/DVS GPIO（mainline 无对应驱动，可跳过） | — |

p207 里 panfrost **probe 成功**、gnome-shell 能把它当硬件 GPU，说明 **probe 那一刻 GPU 是可访问的**
（S-Boot 留下的上电状态 + panfrost 自己 enable 的 `aclk_g3d`/`pclk_sysreg_g3d`）。
第一次 autosuspend 把域断电以后，通用序列恢复不了这个状态 → resume 时读 GPU 就 SError。

## 2. 方案对比与选择

### 2.1 候选方案

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. GENPD_FLAG_ALWAYS_ON（选中，p211）** | 保留 `power-domains`，给 pd_g3d 加 always-on 标志 | ✅ 域永不断电；只在 genpd 层面做，不动 panfrost；不依赖 cmdline；允许 panfrost 正常 runtime suspend（只关 GPU 内部 power）→ 功耗最优的"过渡解" |
| B. `/delete-property/ power-domains`（p210，Lead 正在测） | GPU 不挂 pd_g3d | ✅ 也能绕开（无消费者 → 域不会被 runtime 断电）；⚠️ 依赖 bootargs 的 `pd_ignore_unused`（**去掉 cmdline 就会在 late_initcall 把域断掉，然后 resume 照样 SError**）；破坏 device-genpd 拓扑；与 A 互斥 |
| C. vendor 完整 G3D 上电序列 | 移植 `pm_domains-exynos7420.c` 的 pre/post + sys_pwr + save/restore | ❌ **短期不可行**：第一步就要 RMW `0x10570A04`（CMU_TOPC），该 block 在本板属"读即挂"嫌疑区；且 save_list 需要读 CMU_G3D（可访问）但恢复时机复杂。需先硬件探测（§7） |
| D. `pm_runtime_forbid()`（或 sysfs `power/control=on`） | 永久 pin 住 runtime PM | ⚠️ 机制上可行（`pm_runtime_forbid` 把 usage_count +1 → `rpm_check_suspend_allowed()`（`runtime.c:257-266`）永远返回 `-EAGAIN` → 设备无法 suspend → genpd 不会断电），但 GPU 内部 power 也不关，功耗最高；**无内核改动版**（见 §6 Phase 0）适合做"零重编假设验证"，不建议长期用 |
| E. 改 panfrost 驱动做 genpd 感知 | resume 前检查 genpd 状态等 | ❌ 侵入上游驱动，且没有真正解决"域断电后起不来" |

### 2.2 为什么 A 可行（genpd 源码逐条核对）

`drivers/base/power/domain.c`（本树 6.6）：

| 位置 | 逻辑 | 对 A 的意义 |
|---|---|---|
| `:127` | `genpd_status_on(g) = (g->status == GENPD_STATE_ON)` | 域状态跟踪 |
| `:2066` | `genpd->status = is_off ? OFF : ON`（`pm_genpd_init` 第三参数） | 本驱动用 `!on` 传参：G3D 启动时是 on → `status = ON` |
| `:761-770` | `genpd_power_on()`：`if (genpd_status_on(genpd)) return 0;` | **域一直 ON ⇒ power_on 回调一次都不执行** ⇒ 不完整的 `exynos_pd_power_on()` 永远不会跑，域保持 S-Boot 状态 |
| `:690` | `genpd_power_off()`：`if (genpd_is_always_on(genpd) \|\| ...) return -EBUSY;` | 永不写 `0x105C4100=0` |
| `:929-995` | `genpd_runtime_suspend()`：`genpd_power_off()` **返回值被忽略** | `-EBUSY` 不会让 suspend 失败；panfrost 的 `panfrost_device_suspend()` 正常执行（关 GPU 内部 power） |
| `:1127` | `genpd_sync_power_off()`：`if (!genpd_status_on \|\| genpd_is_always_on) return;` | 系统 suspend 路径同样不断电 |
| `:2043` / `:2093` | `pm_genpd_init()` 里：always-on 域**必须初始为 on**，否则返回 `-EINVAL`，整个域注册失败 | ⚠️ 所以 flag 必须在 `pm_genpd_init()` **之后**置（我们的实现如此） |

`GENPD_FLAG_ALWAYS_ON` 定义：`include/linux/pm_domain.h:67`（`1U << 2`）。

### 2.3 与 p210 的关系（重要）

- p210（删 `power-domains`）能工作的完整条件是：**GPU 不再是 pd_g3d 消费者** AND **`pd_ignore_unused` 在 bootargs 里**（否则 `late_initcall(genpd_power_off_unused)` 会把无消费者域断电 → 后续 panfrost resume 同样 SError）。
  - 已核对：`genpd_power_off_unused` 只在 `pd_ignore_unused` 未设置时执行；当前 board DTS bootargs 确实有 `pd_ignore_unused`。
  - 也就是说 p210 是"两个巧合同时成立"的方案，换 cmdline/改 initcall 行为就退回崩溃。
- p211 不依赖 cmdline；域状态由 genpd 自己通过 `GENPD_FLAG_ALWAYS_ON` 保证。且 GPU 仍挂在 genpd 上（拓扑正确、`/sys/kernel/debug/pm_genpd` 可见、以后实现真序列时无需再改拓扑）。
- **不要把两者叠加**：叠加后等于 p210，ALWAYS_ON 不被执行（也不冲突，只是失去意义）。

## 3. 实现（完整改动）

### 3.1 `arch/arm64/boot/dts/exynos/exynos7.dtsi`（1 行 + 注释）

```diff
 		pd_g3d: power-domain@105c4100 {
 			...
-			compatible = "samsung,exynos5433-pd";
+			/*
+			 * DSH GPU: 专用 compatible 让 exynos-pm-domains 给这个域加
+			 * GENPD_FLAG_ALWAYS_ON ...（详见报告）
+			 */
+			compatible = "samsung,exynos7420-g3d-pd",
+				     "samsung,exynos5433-pd";
 			reg = <0x105c4100 0x20>;
 			#power-domain-cells = <0>;
 			label = "G3D";
 		};
```

- 行号：`exynos7.dtsi:602`（节点）、`:616`（compatible）。
- **为什么新 compatible 放第一位**：OF 匹配按 `compatible` 在节点里的**位置打分**
  （`drivers/of/base.c:320-346` `__of_device_is_compatible()`：`score = INT_MAX/2 - (index << 2)`），
  放第一位保证拿到 `exynos7420_g3d_cfg`，不会被 `samsung,exynos5433-pd` fallback 抢走。
  （保留 fallback 是为了驱动缺失时旧匹配仍可用；本树只有这个驱动匹配两类字符串。）

### 3.2 `drivers/pmdomain/samsung/exynos-pm-domains.c`（~20 行）

**(a) config 结构加字段（`:38-58`）**

```c
struct exynos_pm_domain_config {
	u32 local_pwr_cfg;
	u32 local_pwr_option;
	/*
	 * Keep the domain powered for ever (GENPD_FLAG_ALWAYS_ON).
	 * ...（注释说明 G3D 原因，见文件）
	 */
	bool always_on;                 /* ← 新增，:55 */
	const struct exynos_pd_seq *pre;
	unsigned int n_pre;
	const struct exynos_pd_seq *post;
	unsigned int n_post;
};
```

**(b) G3D 配置（`:193-222`）**

```c
/*
 * Exynos7420 G3D power domain.
 *
 * The vendor power-up sequence needs, besides the LOCAL_PWR_CFG switch:
 *   - CMU_TOP0/TOPC1 "top-to-local" clock gate (ENABLE_SCLK_TOPC1 @ 0x10570A04),
 *   - seven PMU SYS_PWR registers for CMU_G3D (...),
 *   - the pd-option value 0x1101 (LOCAL_PWR_OPTION register base + 0x8),
 *   - save/restore of CMU_G3D + GPU SFRs around power transitions.
 *
 * CMU_TOP0/TOPC1 registers hang the AXI bus when accessed on this board,
 * so the full sequence cannot be implemented safely yet.  Keep the domain
 * in the bootloader state and never power it off.
 */
static const struct exynos_pm_domain_config exynos7420_g3d_cfg = {
	.local_pwr_cfg		= 0xf,
	/* vendor DT: pd-g3d has "pd-option = <0x1101>" (ctc_stock.dts:5806) */
	.local_pwr_option	= 0x1101,
	.always_on		= true,
};
```

> `local_pwr_option = 0x1101` 只在 **power_on 回调被执行**时才会写（即"域启动时是 off"的兜底路径），
> 正常路径（域一直是 on）永远不会执行——不会影响 S-Boot 留下的状态。

**(c) of_match 加条目（`:220-236`，放 5433 条目之前便于阅读）**

```c
static const struct of_device_id exynos_pm_domain_of_match[] = {
	{ .compatible = "samsung,exynos4210-pd", .data = &exynos4210_cfg },
	{ .compatible = "samsung,exynos7420-g3d-pd", .data = &exynos7420_g3d_cfg },  /* ← 新增 */
	{ .compatible = "samsung,exynos5433-pd", .data = &exynos5433_cfg },
	{ .compatible = "samsung,exynos7420-pd", .data = &exynos7420_disp_cfg },
	{ },
};
```

**(d) probe 里在 `pm_genpd_init()` 之后置 flag（`:300-315`）**

```c
	on = readl_relaxed(pd->base + 0x4) & pd->local_pwr_cfg;

	pm_genpd_init(&pd->pd, NULL, !on);

	/*
	 * Must be set after pm_genpd_init(): the latter refuses an always-on
	 * domain that starts out powered off (-EINVAL).  If the domain is
	 * already on (the expected case on this board, the bootloader leaves
	 * G3D powered) genpd will never call exynos_pd_power_on() again and
	 * therefore never power it off either.  If it happens to start off,
	 * genpd powers it on once at the first runtime resume and keeps it on
	 * from then on.
	 */
	if (pm_domain_cfg->always_on) {
		if (!on)
			dev_warn(dev, "%s: always-on domain starts powered off\n",
				 pd->pd.name);
		pd->pd.flags |= GENPD_FLAG_ALWAYS_ON;
	}

	ret = of_genpd_add_provider_simple(np, &pd->pd);
```

## 5. 给 Lead 的测试步骤

### Phase 0（可选，零重编，验证根因假设）

在**现有可启动镜像**（p210，或 p207）上，于 GNOME 启动**之前**把 GPU 设备 runtime PM 永久打开：

```sh
# 手机 root shell（initramfs /etc/rc 或 systemd service 均可）
echo on > /sys/bus/platform/devices/14ac0000.gpu/power/control
```

原理：`pm_runtime_forbid()` 把 usage_count +1 → `rpm_check_suspend_allowed()` 永远 `-EAGAIN`
→ 设备不会 runtime suspend → genpd 不会给 pd_g3d 断电 → 不该再出现 p207 的 SError。
- 若如此：✅ 根因假设（"域断电后无法恢复"）得到硬件证实，p211 必然有效。
- 注意：p207 的崩溃发生在 gnome-shell 启动后约 26s，所以这条命令要在 gdm/gnome 启动前执行。
- 该方案本身只用于验证，不建议长期（GPU 全程满电、功耗最高）。

### Phase 1（p211 正式测试）

1. 用当前树构建/打包（`.config` 不用改），刷机（loader 先 arm watchdog 兜底）。
2. 启动后检查（可以用 USB 串口/网络 shell，或写到文件后用 ramoops/pmsg 读回）：
   ```sh
   # a) 域状态（debugfs；域目录名 = label "G3D"）
   mount -t debugfs none /sys/kernel/debug 2>/dev/null
   cat /sys/kernel/debug/pm_genpd/G3D/current_state   # 期望 "on"（若 "off-0" 则 ALWAYS_ON 没生效）
   cat /sys/kernel/debug/pm_genpd/G3D/devices         # 期望列出 14ac0000.gpu
   cat /sys/kernel/debug/pm_genpd/pm_genpd_summary    # G3D 一行状态 on
   # b) GPU 设备运行时状态
   cat /sys/bus/platform/devices/14ac0000.gpu/power/runtime_status   # active/suspended 会随 job 切换
   cat /sys/bus/platform/devices/14ac0000.gpu/power/control          # auto
   # c) panfrost 是否绑定
   ls /dev/dri/                                       # 应看到 card1 和 renderD128
   dmesg | grep -iE 'panfrost|mali|gpu' | tail -20
   # d) 关键：无 SError / panic（rc=1 表示 grep 无匹配 = 好事）
   dmesg | grep -iE 'SError|panic|Unrecoverable'; echo "grep_rc=$?"
   # e) 期望看到（若有）：无 "always-on domain starts powered off" 警告
   dmesg | grep -i "always-on"
   ```
3. **崩溃复现测试**（p207 的精确触发点）：p207 的 SError 是 gnome-shell 打开/关闭 panfrost
   perfcnt fd（`panfrost_perfcnt_close` → runtime resume）触发的。因此：
   - 启动到 GNOME，**保持 > 60 秒**（覆盖 50ms autosuspend + 反复 resume）；
   - 再开/关几个 GPU 客户端（每次退出都会触发一次 runtime suspend→resume 循环）：
     ```sh
     # 若安装了 mesa-utils（每次 glxinfo 退出都会 put_autosuspend）：
     for i in $(seq 5); do glxinfo -B >/dev/null; sleep 2; done
     # 浏览器看视频/滚动几次（真实 GPU 负载）
     ```
   - 期望：`dmesg` 始终无 SError，`pm_genpd/G3D/current_state` 始终 `on`，
     `/sys/bus/platform/devices/14ac0000.gpu/power/runtime_status` 在 active/suspended 之间来回切。
4. **性能验证**（是否真的硬件加速）：
   ```sh
   glxinfo -B | grep -iE 'renderer|OpenGL'     # 期望 Mali-T760
   # 或
   es2_info 2>/dev/null | grep -i renderer
   journalctl -b | grep -iE 'panfrost|Mali|drm' | tail -30
   ```
   GNOME 动画/浏览器滚动应明显流畅（对比 llvmpipe）。
5. 若成功，记录：`pm_genpd_summary`、`/dev/dri` 列表、`glxinfo -B`、60s 以上无 SError 的 dmesg。

### Phase 2（可选，长期正确解）

等 §7 的 `0x10570A04` 探测结果：
- 可读 → 实现 vendor G3D pre/post 序列（“真”修复：允许域断电，省电）；
- 挂死 → 永久采用 ALWAYS_ON（本方案），把 GPU 域当 always-on 处理（与 5433/7420 的其它在产设备做法一致）。

## 6. 需要 Lead 探测的地址（有手机时顺手做，loader + watchdog）

| # | 地址 | 是什么 | 期望 / 判读 |
|---|---|---|---|
| 1 | **`0x105C4104`** | pd_g3d 的 STATUS/LOCAL_PWR_CFG 镜像 | `0x0000000F` = 域启动时已上电（ALWAYS_ON 最理想）；`0x0` = 启动时是关的（会走兜底路径，见 §4） |
| 2 | **`0x10570A04`** | CMU_TOPC `ENABLE_SCLK_TOPC1`（vendor G3D top clock bit9） | 可读 = 将来可做完整 vendor 序列（Option C）；挂死 = 永久用 ALWAYS_ON |
| 3 | `0x105C4100` | pd_g3d LOCAL_PWR_CFG | 已有可访问性数据（✅ 可访问），顺手确认值 |
| 4 | `0x14AA0000` | CMU_G3D（G3D_LOCK） | 已知 ✅ 可访问（save_list 里要恢复的几个寄存器都在这里） |

> 已知死区（**不要碰**）：`0x14C00000 ~ 0x14CE0000` 整段。
> `0x105D0000`（CMU_TOP0）也不要测（老 data 是读即挂）。

## 7. 风险、功耗与回滚

### 7.1 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 功耗略增 | pd_g3d 域常开（PMU 电源开关不关）；但 panfrost runtime suspend 仍会关 **GPU 内部** power，静态功耗增加有限 | 可接受；Phase 2 实现真序列后可恢复 runtime 断电 |
| 域被外部断电后无法恢复 | 若将来的 firmware/其它路径把 pd_g3d 断掉，ALWAYS_ON 不会主动上电（genpd status 仍认为 on） | 当前无人会断 G3D；若怀疑，读 `0x105C4104` 确认；必要时加“resume 前读 STATUS 校验”调试代码（不建议现在加） |
| 启动时域是 off | 首次 resume 走一次通用上电（无 TOPC1/sys_pwr），可能仍 SError | §7 第 1 项探测；若=0x0，先不要刷 p211，改做 vendor 序列 |
| 与 p210 叠加 | 叠加 = p210（ALWAYS_ON 不生效） | 二者选一；tree 当前是 p211 |
| 其它域 | 新 compatible 只作用于 pd_g3d；`exynos5433_cfg`/`exynos7420_disp_cfg` 未改 | 若发现 DISP 等异常，检查是否误改 |

### 7.2 T760 r0p1 的已知 Mesa 问题（zenlte 经验）

即使电源修好，Mali-T760 r0p1 的 AFBC/CRC/tiling 路径仍可能让 fragment job 挂起或花屏
（zenlte 实测）。缓解（用户态，不需改内核）：

```sh
export PAN_MESA_DEBUG=noafbc,nocrc
```

## 8. 未来：完整 vendor G3D 上电序列（备查）

`los20/.../arch/arm64/mach-exynos/pm_domains-exynos7420-cal.h` 提取：

```c
top_clks_g3d     = { { ENABLE_SCLK_TOPC1,  bit 9 } };                 /* 0x10570A04.b9 */
local_clks_g3d   = { { ENABLE_ACLK_G3D,    bit 1 } };                 /* 0x14AA0800.b1 */
sys_pwr_regs_g3d = {
	{ CLKRUN_CMU_G3D_SYS_PWR_REG,      bit 0 },   /* PMU 0x105C1460 */
	{ CLKSTOP_CMU_G3D_SYS_PWR_REG,     bit 0 },   /* 0x105C14A0 */
	{ DISABLE_PLL_CMU_G3D_SYS_PWR_REG, bit 0 },   /* 0x105C14E0 */
	{ RESET_LOGIC_G3D_SYS_PWR_REG,     bit 0 },   /* 0x105C1520 */
	{ MEMORY_G3D_SYS_PWR_REG,          bit 1 },   /* 0x105C1560 */
	{ MEMORY_G3D_SYS_PWR_REG,          bit 0 },
	{ RESET_CMU_G3D_SYS_PWR_REG,       bit 0 },   /* 0x105C15A0 */
};
save_list_g3d = { DIV_G3D(0x14AA0600), G3D_LOCK(0x14AA0000), G3D_CON(0x14AA0100),
                  G3D_CON1(0x14AA0104), G3D_CON2(0x14AA0108), MUX_SEL_G3D(0x14AA0200),
                  ENABLE_ACLK_G3D(0x14AA0800), ENABLE_PCLK_G3D(0x14AA0900),
                  ENABLE_SCLK_G3D(0x14AA0A00) };
pd_option = 0x1101;   /* → 0x105C4108 */
```

vendor 流程：power_on_pre ①enable top_clks ②enable asyncbridge（G3D 无）③**清 sys_pwr 对应 bit**（注意：
vendor 的 `exynos5_pd_set_sys_pwr_regs()` 是 **clear** bit）→ 写 option → 写 LOCAL_PWR_CFG=0xf → 等 status
→ power_on_post 恢复 save_list（+TMU/G3D GPIO）。
mainline 侧若实现，可仿照现有 `exynos7420_disp_cfg` 的 pre/post 结构，但：
- 第一条 `0x10570A04` 的 **read-modify-write 需要先探测是否可读**；
- save_list 需要“断电前保存”，当前 dp 驱动还没有 save 机制（`exynos_pd_apply_seq` 只有固定值 RMW，需要扩展）。
因此实现成本远高于 ALWAYS_ON；建议等有电源管理需求（如待机）时再做。
