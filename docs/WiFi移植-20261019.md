> 任务：让 G9209 上的 BCM4358（PCIe `14e4:43e9`）在 `/home/duanjb666/linux7420/linux-6.6` 上工作。

> 结论：**可行，代码已落地并通过交叉编译/DTB/整 Image 构建验证**；剩余风险集中在 3 个寄存器块的可访问性和 S-Boot 遗留的时钟状态，已给出逐步验证与回退办法。

## 0. TL;DR（给 Lead 的 5 句话）

1. **主线没有任何 Exynos7420 PCIe host 支持**：`drivers/pci/controller/dwc/pci-exynos.c` 只 match `samsung,exynos5433-pcie`；7420 的 PHY、时钟门控、DBI 访问方式都是三星私有的，**仅加 compatible 字符串不可能工作**。已新写驱动 `drivers/pci/controller/dwc/pci-exynos7420.c`（701 行，基于原厂 3.10 BSP 逐段移植）。
2. **brcmfmac 不需要改**：`pcie.c` 已有 `BRCM_PCIE_4358_DEVICE_ID (0x43e9)`，固件名固定为 `brcm/brcmfmac4358-pcie.bin` + `brcmfmac4358-pcie.txt`（nvram）。已从 **G9209 原厂 system.img** 提取芯片为 **BCM4358 A3** 的固件（7.112.53.12）与 SEMCO B85B NVRAM，放进内核树，用 `CONFIG_EXTRA_FIRMWARE` 内建（不需要改 ramdisk/uniLoader）。
3. **供电假设需要修正**：原厂 DTS 的 `wlan` 节点**没有**任何 regulator/电源属性，dhd 也只控制 `WL_REG_ON(gpf4-6)`；原厂根本没有"WLAN LDO"节点。⇒ 模块电源是常开 rail，`WL_REG_ON` 只是模块内部使能，**PMIC 不需要动**（如果后面上电失败再查 S2MPS15/S2MPB02 的 always-on 组）。
4. **真正的风险是三个未实测地址**：`0x1005265C`（SYSREG PHY 选择）、`0x156F00E4`（PHY PCS）、以及 `ELBI 0x15660000 / PHY 0x15630000 / DBI 0x157B0000` 在门控打开前不可访问。驱动已按"**先开 CMU_FSYS1 门控 + PMU 上电，最后才碰 IP**"的顺序写，并为前两个地址留了 `samsung,skip-phy-sysreg` / `samsung,skip-phy-pcs` 单属性跳过开关。
5. **有强证据说明这条路走得通**：参考的 zenlte 主线 6.6 移植（同 SoC、同 BCM4358、同 PCIe1）**WiFi 已工作**（其交接文档："WiFi/蓝牙/浏览器/桌面均已完成且稳定"；systemd `exynos7420-pcie.service` + brcmfmac），其 DTS 的 pcie 节点接口（`dbi/elbi/phy/block/cmu/phy_pcs/config` + `perst-gpios` + `wl-en-gpios` + `dma-ranges`）与本驱动完全对齐。

**给 Lead 的动作**：① 按 §4 改 `.config`（6 项 + 2 行 EXTRA_FIRMWARE）；② `./build_mainline.sh pNNN`；③ **loader 先 arm watchdog** 再 boot；④ 按 §5 的日志地标定位；⑤ 挂死就用 §6 的三级回退。如果 §5 Step 0 的探测表明三个块硬不可访问，则看 §7 的替代方案（USB WiFi dongle）。

## 1. 调研结论

### 1.1 主线 PCIe host 现状：**没有 7420 支持，必须新驱动**

| 项 | Exynos5433（主线唯一支持） | Exynos7420（本机） |
|---|---|---|
| compatible | `samsung,exynos5433-pcie` | `samsung,exynos7420-pcie` |
| DBI | 0x1570_0000 | **0x157B_0000** |
| ELBI | 0x156B_0000 | **0x1566_0000** |
| PHY | 0x1568_0000，独立驱动 `drivers/phy/samsung/phy-exynos-pcie.c` | **0x1563_0000** + CAL 表硬编码 + SYSREG 控制，主线无 PHY 驱动 |
| 时钟 | CCF（`cmu_fsys` 的 CLK_PCIE 等） | CMU_FSYS1 12 个门控，**mainline clk-exynos7.c 没有定义**，只能直接 RMW |
| DBI 访问 | sideband 位（ELBI 0x11C/0x120 bit21） | **必须做 L1 退出舞蹈**（ELBI 0x40=1、0xF4=0 → 访问 → 0xF4=1、0x40=0） |
| PMU | PCIe PHY isolation 0x730 | **0x105C_071C bit0**（PHY 上电） |
| 其他 | — | CMU Q-Channel 强制开 `0x156E0F00 bit0`；SYSREG `0x1005265C` |

- 主线 `drivers/pci/controller/dwc/pci-exynos.c`（443 行）OF match 只有 5433；Kconfig `PCI_EXYNOS`。当前 `.config` 里还是 `CONFIG_PCI_EXYNOS=m`，而 `build_mainline.sh` 只 `make Image`（不编模块）⇒ **即使不写新驱动，模块形态也不会被加载**。
- 原厂实现：`/home/duanjb666/los20/kernel/samsung/universal7420/drivers/pci/host/`
  - `pci-exynos.c` 2210 行（公共流程 + 通知/电源管理/调试，含团队之前为 MDM 打的补丁）
  - `pci-exynos7420.c` 111 行（时钟表：ch1 10 个 pcie clk + 2 个 phy clk）
  - `pci-exynos7420_cal.c` 56 行（**PHY 26 字 common + 41 字 trsv 配置、PCS/PMA 复位、SYSREG 操作**）
  - `pcie-designware.c` 1013 行（3.10 版 DWC core；**其 ATU/MSI/MISC 寄存器偏移与主线 6.6 DWC 完全一致**——这是本次移植最大的有利条件）
- **DWC core 兼容性验证**（源码逐项对照）：ATU viewport `0x900`、ATU ctrl/base/target `0x904..`、MSI addr `0x820`、MSI enable `0x828`、MSI status `0x830`、DBI_RO_WR_EN `0x8BC` 全部一致；`dw_pcie_setup_rc()` 写完 RC 后 `dw_pcie_wait_for_link()` 的链路判定我们换成 ELBI 0x74（见下）。
- 原厂关键初始化序列（ch1，逐条从 `pci-exynos.c` 提取，全部已实现在新驱动里）：
  1. `WL_REG_ON` 拉高（dhd glue `dhd_wlan_power`）→ 调 `exynos_pcie_poweron(1)`；
  2. 使能 12 个 CMU_FSYS1 门控（pcie_clks[0..8] + ref clock `sclk_phy_fsys1_gated`）；
  3. `PMU 0x105C071C` bit0 = 1（PHY 上电）；
  4. PHY 全断电解除：`phy+0x54 &= ~(0xF<<3)`、`phy+0x138/0x13C=0`；
  5. `PERST(gpg2-0)` 拉高 → 等 18–20 ms；
  6. ELBI：`0xF4=1`（APP_REQ_EXIT_L1_MODE=HW）、`0xF0=1`（CORE_RESETN_DISABLE）、`CMU 0x156E0F00 |= 1`（Q-Channel 强制开）；
  7. **combo PHY CAL**：SYSREG `0x1005265C` 清 bit[5:4]、置 bit2 → ELBI `+0x130`(PCS_G_RST)、`+0x134`(PMA_INIT_RST) 各 10µs 脉冲 → 写 26+41 个 PHY 寄存器 → `0x156F00E4 = 2` → SYSREG bit7（CMN_RST）20µs 脉冲；
  8. ELBI `0x38=1`（L1 bug fix）、清 ELBI `0x18` bit1（BUS_EN）；
  9. DBI 访问舞蹈（见 1.1 表）后 `dw_pcie_setup_rc()`；
  10. ELBI `0x2C=1`（LTSSM enable），轮询 ELBI `0x74 & 0x1F ∈ [0x0D,0x15]` 判定 link up；
  11. 打开 ELBI MSI 中断源（`IRQ_EN_LEVEL bit1`），MSI 走 DWC `0x820/0x828/0x830`。

### 1.3 供电 / 复位 / 时钟（以原厂 DTS + dhd + 3.10 驱动为准）

- **供电：原厂没有 WLAN regulator**
  - `ctc_stock.dts` 的 `wlan { compatible = "samsung,brcm-wlan"; gpios = ...; pinctrl-0 = <&cfg_wlanen &wlan_host_wake>; }` —— 只有 GPIO/pinctrl，无 `*-supply`；
  - dhd glue（`dhd_custom_exynos.c: dhd_wlan_power()`）只做 `gpio_direction_output(wlan_pwr_on, onoff)` 再 `exynos_pcie_poweron(1)`；全文件无 regulator API；
  - 结论：**不需要改 PMIC**；如果 WiFi 不亮，再查 S2MPS15/S2MPB02 的 always-on LDO（原厂 DTS 里没有 WLAN 专属 LDO 的线索）。
- **复位/使能（用户给的事实，已与原厂 DTS 核对一致）**：

| 信号 | 引脚 | 原厂 pinctrl | 驱动行为 |
|---|---|---|---|
| WLAN_EN / WL_REG_ON | `gpf4-6` | func1 output | `wl-en-gpios`，probe 时拉高，之后保持 |
| PERST（低有效） | `gpg2-0` | func1 output | `perst-gpios`（GPIO_ACTIVE_LOW），probe 时先保持复位，`host_init` 里释放 |
| CLKREQ | `gpf0-6` | func2 | pinctrl default |
| HOST_WAKE | `gpa2-3` | func0xf EINT, pull-up | 只配置 pin；brcmfmac 基本功能不需要它，本轮**没有注册 wake IRQ** |
| （原厂还有）link reset | `gpg2-2` | func2 + 不同 pull 的 "pcie_reset" 状态切换 | 仅链路重试用；**本轮未用** |

- **时钟门控（全部在 CMU_FSYS1 @ 0x156E_0000，来源原厂 `clk-exynos7420.c` 门控表 + `regs-clock-exynos7420.h`）**：

| 寄存器 | bit | 时钟 |
|---|---|---|
| `0x800` ENABLE_ACLK_FSYS1 | 9,10,11,12,13,17,18,20,21,24 | `aclk_combo_phy_pcs_pclk_wifi1`、`aclk_pcie_wifi1_dbi/slv/mstr_aclk`、`aclk_ahb2axi_pcie_wifi1`、`aclk_bts_wifi1/embedded`、`aclk_xiuasync_tlx400_axius_wifi1`、`aclk_axius_tlx400_wifi1`、`aclk_xiu_wifi1x` |
| `0x900` ENABLE_PCLK_FSYS1 | 22,26,27,28,29,31 | `pclk_async_combo_phy_wifi1`、`pclk_bts_wifi1/embedded`、`pclk_xiuasync_axisel/tlx400_axius_wifi1`、`pclk_tlx400_wifi1` |
| `0xA04` ENABLE_SCLK_FSYS11 | 0,8,12,16 | `sclk_pcie_link_wifi1_gated`、`sclk_tlx400_wifi1_tx/slow`、**`sclk_phy_fsys1_gated`（PHY 参考时钟）** |
| `0xA08` ENABLE_SCLK_FSYS12 | 8,12 | `phyclk_pcie_wifi1_rx0/tx0_gated` |
| `0xA0C` ENABLE_SCLK_FSYS13 | 28 | `sclk_combo_phy_wifi1_26m_gated` |

  - 主线 `drivers/clk/samsung/clk-exynos7.c` 的 FSYS1 只有 MMC/UFS 门控，**没有 PCIe 门控定义**；本轮按约束**没有改 clk 驱动**，改为在新 PCIe 驱动里直接 RMW（与 zenlte 主线移植一致）。以后可以改成正规 CCF 门控（那时可以给 DTS 加 `clocks`）。
  - 这些门控的父 mux 与 UFS 共用 FSYS1 的 `mout_aclk_fsys1_200_user`（板级 DTS 已用 fixed-clock 200MHz 顶替 TOP1），**UFS 能工作说明该 mux 已被 S-Boot 配到 200MHz 档**，这是降低时钟风险的重要论据。PHY 参考时钟实际频率（24 还是 26MHz）无法静态确认，CAL 表按原厂注释是 24MHz gen1、而门控名是 26m，若 link 不 train 这是可调项。
- **其他关键寄存器**：`PMU 0x105C071C` bit0=PHY 上电（0x105C0000 块已实测可访问，0x105C0720 同块 UFS PHY 也在用）；`0x156E0F00` bit0=CMU Q-Channel 强制开；`0x1005265C`=SYSREG（PHY refclk 选择 + CMN_RST）；`ELBI+0x130/0x134`=PCS/PMA 复位；`0x156F00E4`=PHY PCS。

## 2. 改动清单（全部在允许目录内）

### 2.1 新增：`drivers/pci/controller/dwc/pci-exynos7420.c`（701 行）

新 host 驱动。结构：

| 段 | 内容 |
|---|---|
| 寄存器定义 | ELBI / interrupt / DBI 舞蹈 / CMU_FSYS1 门控 / PMU / PHY 偏移（全部带原厂出处注释） |
| `exynos7420_pcie_read_dbi()/write_dbi()` | 7420 专有 DBI 访问舞蹈（`raw_spinlock` 保护，IRQ 上下文安全） |
| `exynos7420_pci_ops`（own config） | 让 root bus 的自己配置空间访问走 DBI 舞蹈（对应 5433 驱动里的 sideband 版本） |
| `link_up/start_link/stop_link` | ELBI `0x74` 状态判定、`0x2C` LTSSM 开关 |
| `gates_set()` | 直接 RMW CMU_FSYS1 的 12 个 PCIe 门控（带注释：将来应改 CCF） |
| `pmu_power()` / `phy_all_power_down()` | 原厂 3.10 的 PHY 上电/断电序列 |
| `phy_config()` | 原厂 CAL 序列（26+41 字表 + SYSREG + PCS/PMA 复位 + CMN_RST 脉冲） |
| `irq_handler()` | 清 ELBI pulse/level/special，然后 `dw_handle_msi_irq()`（MSI 从 ELBI IRQ 派发） |
| `host_init()` | PERST 释放 → 20ms → ELBI 配置 → PHY CAL → L1 bugfix → 中断/总线配置 → 接管 own-conf ops |
| `probe()` | 取资源/GPIO/IRQ → **先开时钟门控 + WL_EN + PMU 上电** → 清中断 → 请求 IRQ → `dw_pcie_host_init()`；失败全部回滚 |
| `remove()` | 反序断电 |

设计要点：
- **复用主线 DWC core**（`dw_pcie_host_init`/`dw_pcie_setup_rc`/ATU/MSI 域/`pci_host_probe` 全部现成），不自带 3.10 的 `pcie-designware.c`；
- `pp->msi_irq[0] = -ENODEV` 阻止 DWC 装 chained MSI handler，改由我们的 ELBI handler 调 `dw_handle_msi_irq()`（这是 BCM4358 MSI 能工作的关键）；
- 供电顺序严格照原厂：**门控 → WL_EN → PMU → 再碰 ELBI/PHY**（否则未上电 IP 访问会 AXI 挂死）；
- 两级"跳过开关"（DTS 属性）：`samsung,skip-phy-sysreg`、`samsung,skip-phy-pcs`，用于硬件定位挂死点；
- 每个危险阶段都有 `dev_info` 地标（屏幕/串口能直接看到最后一步）。

### 2.4 修改：`arch/arm64/boot/dts/exynos/exynos7420-zeroflte.dts`（第 638–733 行，追加）

- `#define DSH_ENABLE_PCIE_WIFI 1` 总开关（改 0 即整体关闭，回到当前可用基线）；
- `&pinctrl_bus1`：`pcie1_clkreq`(gpf0-6 func2)、`pcie1_perst`(gpg2-0 output)、`cfg_wlanen`(gpf4-6 output)；

- **根节点下**（不是 `&soc`！）`pcie1: pcie@157b0000`：
  - `reg`/`reg-names`：`dbi/elbi/phy/block/pmu/cmu/phy_pcs/gates/config` 共 9 段（与 zenlte 主线 DTS 的 7 段对齐，另外补 `pmu` 和 `gates`）；
  - `interrupts = <GIC_SPI 205 IRQ_TYPE_LEVEL_HIGH>`（原厂 `pci-exynos.c` 的 `IRQ_PULSE`，实测 GIC SPI 205）；
  - `ranges` 只给 MEM 窗口（0x1C011000, 0x3FEEFFF）；**`dma-ranges` 做 4GB 恒等映射**（EP→host DMA 需要 inbound iATU，zenlte 也是这么写的）；
  - `perst-gpios = <&gpg2 0 GPIO_ACTIVE_LOW>`、`wl-en-gpios = <&gpf4 6 GPIO_ACTIVE_HIGH>`；
  - `pinctrl-0` 四项。

## 5. 给 Lead 的硬件验证步骤

### Step 0（强烈建议先做）：用 loader + 看门狗探测 PCIe 地址

沿用 `硬件实测-PERIC1与PMIC-20261018.md` §1 的 `safe_probe.py` 方法（loader `watchdog arm` → `mrd` → 挂死则由 WDT ≈32s 复位）：

| 地址 | 块 | 期望/说明 |
|---|---|---|
| `0x156E0800` / `0x156E0900` / `0x156E0A04` / `0x156E0A0C` | CMU_FSYS1 门控寄存器 | **应可读**（CMU_FSYS1 已被 UFS 证明可访问） |
| `0x157B0000` | PCIe1 DBI | 门控未开时**可能挂死**；挂死不代表不可用，只说明 loader 阶段没时钟 |
| `0x15660000` | PCIe1 ELBI | 同上 |
| `0x15630000` | PCIe1 combo PHY | 同上 |
| `0x156E0F00` | CMU Q-Channel（CMU_FSYS1 同页 0xF00） | 应可读 |
| `0x156F00E4` | PHY PCS | **未知，重点探测对象** |
| `0x1005265C` | SYSREG（PHY refclk/CMN_RST） | **未知，重点探测对象**（同一 SYSREG 块的 `0x10050054` 原厂会写，理论可访问，但本内核从未碰过） |
| `0x105C071C` | PMU PCIe PHY control | 应可读（0x105C0000 已实测可访问；0x105C0720 UFS PHY 在用） |

> 注意：loader 阶段读到 0x1566/0x1563/0x157B 挂死**不能**判定内核阶段也不可用——内核阶段我们会先开 12 个门控 + PMU 上电。但 `0x1005265C`/`0x156F00E4` 与 PCIe 门控无关，若 loader 读就挂，则内核阶段大概率也挂，需要加 `samsung,skip-phy-sysreg` / `samsung,skip-phy-pcs`（见 Step 2）。

| 有 `releasing PERST`、卡在 `configuring combo PHY` 前后 | **`0x1005265C` SYSREG** 或 `0x156F00E4` PHY PCS | 加 `samsung,skip-phy-sysreg;` 或 `samsung,skip-phy-pcs;`（两个属性驱动都实现了） |
| 到 `starting LTSSM` 但无 link up | 时钟频率不对（PHY refclk 24/26MHz）、PERST/CLKREQ、WL_EN 时序、PHY CAL 值 | 保持看门狗；把 `loglevel` 拉高看 DWC 的 `Phy link never came up`；下一步试 24MHz/26MHz 变体（需要时我来加第二张 CAL 表） |
| link up 但枚举不到 / 枚举卡死 | config 窗口/ATU（0x1C000000）、`ranges` 翻译 | 检查 `cat /proc/iomem | grep -i pcie`、`iATU: unroll F, ? ob, ? ib` 数字（ob 必须 >1、ib ≥1，`dma-ranges` 才能生效） |

## 7. 风险 / 替代方案

### 7.1 剩余风险（按概率/影响排序）

| # | 风险 | 说明 / 缓解 |
|---|---|---|
| R1 | **`0x1005265C` SYSREG 访问挂死** | 该块本内核从未访问过（现有 8 核/UFS/GPU/显示都不碰它），不在已实测安全清单里。缓解：`samsung,skip-phy-sysreg`；如果必须写，可用 loader 在 watchdog 下先读验证，或从 8 核修复的 `0x10050054` 访问记录推断同块可读（原厂 `pmu.c` 会写 SYSREG，说明硬件上可访问）。**这是本移植第一风险点**。 |
| R2 | **`0x156F00E4` PHY PCS 访问挂死** | 同上；`samsung,skip-phy-pcs`。写入值只有 `0x2`，跳过可能仍能 link（待实测）。 |
| R3 | 门控顺序/PMU 上电不生效 → ELBI/PHY/DBI 挂死 | 驱动已按原厂顺序先门控再访问；第一次测试必须 arm WDT。 |
| R4 | PHY 参考时钟频率（24 vs 26MHz）导致 PLL 不锁/link 不 train | 原厂 CAL 注释写 "24MHz gen1"，但门控名是 `26m`；板级 DTS 目前 `fsys1_phy` 固定 26MHz。若 link 不 up，下一步加 24MHz 版 CAL 表（改动小）。 |
| R5 | MSI 不工作（BCM4358 收不到/发不出 MSI） | brcmfmac 强制 `pci_enable_msi`；本驱动已实现 ELBI→DWC MSI 派发。若失败，看 `/proc/interrupts` 的 `exynos7420-pcie` 计数和 dongle 启动超时。 |
| R6 | brcmfmac 与三星固件 ABI 不兼容（`shared version`） | 换 linux-firmware 版固件（§3.2）。 |
| R7 | NVRAM 模组变体不对 → RF 参数差/校准失败 | 换 SEMCO/murata/wisol 变体；或先不加载 NVRAM（optional）对比行为。 |
| R8 | `dma-ranges` 恒等映射与 IOMMU/CMA 冲突 | PCIe 没有 SYSMMU 绑定，当前 `CONFIG_EXYNOS_IOMMU` 的改动不会 attach PCIe；若出现 DMA 问题，先看 `iATU ... ib` 数量。 |

### 7.2 如果 PCIe host 完全不可行（例如 R1/R2 实测必挂且无法绕开）

**结论标准**：loader 在 watchdog 下确认 `0x1005265C` / `0x156F00E4` 必挂；且跳过这两个块后 DBI/ELBI/PHY 仍无法访问（即 IP 块本身不可用）。

替代方案（按现实性排序）：
1. **USB WiFi dongle**（最现实）：本机 USB 已完全可用（ACM shell）。推荐芯片：
   - `ath9k_htc`（AR9271，2.4G，驱动/固件成熟；`CONFIG_ATH9K_HTC`+`CONFIG_ATH9K_HTC_DEBUGFS`? + firmware `htc_9271.fw`）；
   - `rtl8xxxu`（RTL8188EU/8192CU，`CONFIG_RTL8XXXU`，需要 `rtlwifi/rtl8192cufw.bin` 等固件）；
   - 或 `mt7601u`（`CONFIG_MT7601U` + `mt7601u.bin`）。
   - 工作量 ≈ 改 `.config` + 把固件内建（EXTRA_FIRMWARE）+ 验证 `wpa_supplicant`，**1–2 个构建周期**即可上网；性能/集成度不如内建 BCM4358，但能立刻交付 WiFi 功能。
2. **SDIO WiFi**：本板 BCM4358 是 PCIe 版，没有 SDIO 走线；不适用。
3. **继续啃 PCIe**：如果 R1/R2 能被 loader 证伪（即地址其实可访问），按 §5 Step2 的表逐项调，仍在可行范围内。
