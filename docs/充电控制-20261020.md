## 0. TL;DR（给 Lead / 用户）

1. 原驱动只读，**充电配置完全靠 S-Boot**。用户报告"充不进去电"，v2 现在能做三件事：
   - **只读诊断**（每次 probe 自动打印，绝对安全）：CHG_CNFG_00 的 `CHG_EN` 是否置起、输入限流/快充电流/浮充电压的实际编码、INT_OK/DTLS 充电状态、**MUIC 端口类型**（PC USB 口 vs 墙充）、**FG 实测电流**；
   - **安全可控写**（默认关闭）：`safe` 模式先用 500mA 输入/500mA 快充把充电打开并观察，确认电流为正后再 `full` 上 2100mA/1800mA；
   - 修掉两个"看着像充不进电"的隐性问题：**充电看门狗 WDTEN**（若 S-Boot 开了 WDT 而内核从不 kick，MAX77843 会在看门狗到期后挂起充电）和 **CHG_CNFG_06 写保护**（不解锁则一切配置写入被芯片静默忽略）。
2. 现场第一步只做只读判读（§4 Step 1），**5 分钟就能定性**：是没使能、限流太小、PC 口供电不足、还是总线/硬件问题。
3. 安全红线：默认 `charge_enable=0` 不写任何寄存器；写入有 readback 校验；写序为"输入限流 → 快充电流 → 浮充电压 → 最后才 CHG_EN"；PC USB 口/未知端口强制 500mA 上限；不碰 `CHG_CNFG_01/10/11`。
4. **测充电时务必关屏/退出 GNOME**（2K 屏 + WiFi + GPU 功耗可能超过 USB 口供电，边充边放电会得出错误结论）。

## 2. "充不进去电"的四个候选原因（按可能性排序）

### 2.1 充电没使能：`CHG_CNFG_00(0xB7)` bit0 `CHG_EN = 0`
S-Boot 退出/切 kernel 时可能把充电关了。判据：诊断打印 `CHG_EN=0`。
处置：`echo 1 > /sys/module/max77843_charger/parameters/charge_enable`（safe 模式自动打开）。

### 2.2 输入限流太小 / 端口本身供不上
`CHG_CNFG_09(0xC0)` 编码：`code<=3` → 100mA，其余约 `code*33mA`；PC USB 口（SDP）最大 500mA。
若 `input_limit=100mA` 而系统功耗 >100mA ⇒ 永远充不进。
另外 **2K 屏+WiFi+GPU 常开时整机功耗可能 > 500mA**，即使充电正常也净放电（H-power 假设）。
判据：诊断里 `input_limit`、`MUIC_chg_type`（`USB-SDP`=PC 口 500mA；`DEDICATED-DCP`=墙充）。

### 2.3 充电看门狗（WDTEN）— **本次新增的最可疑项**
`CHG_CNFG_00` bit4 = `WDTEN`。若 S-Boot 打开了充电看门狗，而内核不周期性写
`CHG_CNFG_06(0xBD)` 的 `WDTCLR` 位，芯片看门狗到期后会**挂起充电**——
表现就是"插着线，但电量只掉不涨"。
原厂 3.10 驱动在 `max77843_get_charging_health()`（`drivers/battery/max77843_charger.c:218-220`）
和 probe（`:2442-2444`）里每次 kick：`update_reg(CNFG_06, MAX77843_WDTCLR, CHG_CNFG_06_WDTCLR_MASK)`。
我们的 v2 在 apply 里：
- 先 `WDTCLR` kick 一次；
- 再在 `CHG_CNFG_00` 里**清掉 WDTEN**（我们不做周期 kick，关掉看门狗最稳；芯片自身的温度/定时/终止保护仍在）。
判据：诊断打印 `WDTEN=1` + 充电状态显示 `charger off`/`done` 但电流为负。

### 2.4 写保护没解锁 → 配置写了也没用
`CHG_CNFG_06` bits[3:2] 是写保护位，等于 `0b11` 才是解锁；不解锁时写 CNFG_00/02/04/09 **可能被芯片静默忽略**。
v2 的 `unlock` 流程：读 CNFG_06 → 若未解锁则写 `0x0C` → msleep(20) → 重试最多 10 次；
每次写寄存器后 **readback 校验**，不匹配则 re-unlock 重试一次，仍失败报 `-EIO` 并打 `verify failed (write protected?)`。

## 3. v2 驱动实现（`drivers/power/supply/max77843-charger.c`）

### 3.1 只读诊断（probe 自动打印，随时可再触发）

寄存器 dump（`dev_info`，只进 dmesg，不刷串口）：

```
CHG_INT(0xB0) CHG_INT_MASK(0xB1) CHG_INT_OK(0xB2)
CHG_DTLS_00(0xB3) CHG_DTLS_01(0xB4) CHG_DTLS_02(0xB5)
CHG_CNFG_00(0xB7) 01(0xB8) 02(0xB9) 03(0xBA) 04(0xBB)
CHG_CNFG_06(0xBD) 07(0xBE) 09(0xC0) 10(0xC1) 12(0xC3)
```

解码摘要（一条 dev_info，方便 grep）：

```
DSH-CHG probe decoded: CHG_EN=%d BUCK=%d OTG=%d BOOST=%d WDTEN=%d |
  fast=%d mA | float=%d mV | input_limit=%d mA | prot=locked/unlocked |
  INT_OK=0x%02x [CHGIN_OK=? WCIN=? CHG=? BAT=? BATP=?]
DSH-CHG probe detail: VBUS=valid/absent | charge_state=pre-qual/CC/CV/top-off/done/
  high-temp fault/thermal shutdown/timer fault/charger off | battery=... |
  MUIC_chg_type=N(NAME)
DSH-CHG probe MUIC(0x25): STATUS1(ADC) STATUS2(CHGTYP) STATUS3
DSH-CHG fuel-gauge current = N uA (charging/discharging)
```

判读表：

| 诊断输出 | 结论 | 下一步 |
|---|---|---|
| `CHG_EN=0` | 充电被关（S-Boot/复位导致） | safe 使能 |
| `CHG_EN=1, WDTEN=1` | 看门狗可能已挂起充电 | `charge_enable=1`（会清 WDTEN+kick）|
| `CHG_EN=1, input_limit=100` | 限流太小 | safe 使能（500mA）|
| `CHG_EN=1, input_limit>=500, MUIC=USB-SDP` | PC USB 口只有 500mA，整机功耗可能更大 | **换墙充**；关屏测试 |
| `VBUS=absent` / `MUIC=NONE` | 没检测到有效输入（线/口/MUIC 路径）| 换线/换口；查 MUIC |
| `charge_state=charger off` 且 `FG current<0` | 充电被暂停（WDT/温度/输入不足）| 先 safe 使能，再看温度 |
| 寄存器全失败/`does not respond` | i2c-gpio/地址问题 | `i2cdetect -l | grep max77843`、`i2cdetect -y N` |

### 3.2 可控写（默认关闭）

**module 参数**（built-in，路径 `/sys/module/max77843_charger/parameters/`）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `charge_enable` | **0** | 0=完全不写；1=按 safe 模式写 CNFG_00/02/04/09 |
| `fast_chg_ma` | 2100 | CHG_CNFG_02 快充电流（mA，clamp 100-3150） |
| `float_mv` | 4350 | CHG_CNFG_04 浮充电压（mV，clamp 3650-4700） |
| `input_limit_ma` | 1800 | CHG_CNFG_09 输入限流（mA，clamp 100-4000） |
| `safe_bringup` | 1 | 1=非 `full` 时把输入/快充都压到 500mA |
| `dump` | 0 | 写 1 立即打印全部诊断 |

**sysfs 单次命令**（`/sys/class/power_supply/max77843-charger/charge_ctrl`，写字符串）：

| 命令 | 行为 |
|---|---|
| `dump` | 打印全部诊断（同 `dump=1`） |
| `enable` / `safe` | 安全模式：500mA 输入+500mA 快充，打开 CHG_EN |
| `full` | 按参数写 1800mA/2100mA/4350mV（MUIC 若报 500mA 类端口仍强制 500mA 上限并警告） |
| `disable` | 只清 CHG_EN |
| `unlock` | 解锁并报告写保护状态 |
| `kick` | 踢一次充电看门狗 |

**写序（安全）**：
1. `CHG_CNFG_09` 输入限流（先限制从电源取电，绝不超配）
2. `CHG_CNFG_02` 快充电流
3. `CHG_CNFG_04` 浮充电压
4. **最后** `CHG_CNFG_00`：置 `CHG|BUCK`，清 `OTG|BOOST|WDTEN`

每次写后 readback 校验（`DSH-CHG W ... OK` 或 `verify failed`）。
最后 `msleep(800)` 再 dump 一次，并 `power_supply_changed()` 让 upower 刷新。

**编码（vendor 公式，原厂行号见附录）**：
- 快充电流：`code = round(mA/50)`，`code<=2` 视为 100mA；100..3150mA。
- 输入限流：`code<=3` → 100mA；否则 `code = round(mA*3/100)`（code=54 ⇒ 1800mA，code=15 ⇒ 500mA）。
- 浮充电压：`code = round((mV-3650)/25)`（4350mV ⇒ 28=0x1C；4400 ⇒ 30）。

### 3.3 与 v1（interim 版）的差异

| 项 | interim（display-fixer 版） | v2（本版） |
|---|---|---|
| 参数名 | `write_enable/fast_charge_ua/...` | **`charge_enable/fast_chg_ma/float_mv/input_limit_ma/safe_bringup`** |
| CHG_CNFG_06 写解锁 | ❌ 无（写配置可能全被忽略） | ✅ unlock + 重试 |
| 充电看门狗 | ❌ 未处理（可能挂起充电） | ✅ kick + 清 WDTEN |
| 写序 | CHG_EN 先写 | ✅ 限流→电流→电压→最后使能 |
| 写校验 | 仅最后整体 dump | ✅ 每次写 readback + 重试 |
| MUIC 端口类型 | ❌ 无 | ✅ 只读 0x25，SDP 强制 500mA |
| 安全分级 | 无 | ✅ safe(500mA) / full 两级 |
| sysfs 命令 | 无 | ✅ `charge_ctrl`（dump/enable/full/disable/unlock/kick） |

## 4. 上机测试方案（手机空出来后按顺序做）

> 前置：`i2cdetect -l | grep -i max77843` 能看到 i2c-gpio 总线；`dmesg | grep -i "charger registered"` 正常。
>
> **可选（推荐给低电量现场）**：在 `uniLoader/main/diag.c` 的 bootargs 加
> `max77843_charger.charge_enable=1`，内核 probe 时就自动按 safe 模式（500mA）开充电，
> 不依赖 GNOME；确认墙充后再 `echo full > .../charge_ctrl` 上大电流。

### Step 0：准备（不写寄存器）
```sh
# 关屏/退出 GNOME（重要：降低整机功耗，否则测不出净充电）
systemctl stop gdm 2>/dev/null
# 看当前所有读数
dmesg | grep DSH-CHG
cat /sys/class/power_supply/max77843-fuelgauge/{capacity,voltage_now,current_now,temp,status}
cat /sys/class/power_supply/max77843-charger/{online,status,input_current_limit,constant_charge_current_max}
upower -d | grep -E "percentage|state|on-battery"
# 再触发一次 dump（不写任何寄存器）
echo 1 > /sys/module/max77843_charger/parameters/dump
dmesg | grep DSH-CHG | tail -25
```
记录：`capacity`、`current_now`（放电应为负/充电为正）、`CHG_EN`、`input_limit`、`MUIC_chg_type`、`WDTEN`。

### Step 1：只读判读（定性）
按 §3.1 判读表判断，把结果发我/记录。**这一步不需要写任何寄存器**。

### Step 2：safe 使能（500mA，PC USB 口也可安全做）
```sh
echo 1 > /sys/module/max77843_charger/parameters/charge_enable
dmesg | grep DSH-CHG | tail -30
sleep 20
cat /sys/class/power_supply/max77843-fuelgauge/{current_now,capacity}
```
期望：日志出现 `write protection unlocked` → 各 `DSH-CHG W ... OK` → `charging enabled`；
`current_now` 变正（充电）并增大；`dmesg` 的 `charge_state=fast-charge CC/CV`。
若 `verify failed (write protected?)`：写保护没解锁 → 报我。
若 `VBUS=absent` / `MUIC=NONE`：先处理输入检测（换线/口），不是软件问题。

### Step 3：full 使能（仅墙充 / DCP）
```sh
# 确认 MUIC_chg_type=DEDICATED-DCP 再用 full
echo full > /sys/class/power_supply/max77843-charger/charge_ctrl
dmesg | grep DSH-CHG | tail -25
sleep 30
cat /sys/class/power_supply/max77843-fuelgauge/current_now   # 期望 >1000mA 量级（2100mA 设置）
```
> PC USB 口做 full 会被自动压回 500mA（日志有警告），这是保护不是 bug。

### Step 4：长充观察（30-60 min）
- 每 5 分钟记录 `capacity/current_now/voltage_now/temp`；
- 期望 `capacity` 单调上升、`voltage_now` 向 4.35V 靠近、`temp` <45℃；
- 拔掉再插上：`online` 0→1，`charge_state` 从 `charger off` → `CC`。

### Step 5：恢复/回滚
```sh
echo disable > /sys/class/power_supply/max77843-charger/charge_ctrl   # 只关充电
# 或
echo 0 > /sys/module/max77843_charger/parameters/charge_enable        # 下次不再自动写
# 彻底回滚：重刷不含 charge_enable 设置的镜像（默认 0 = 与旧只读版等效）
```

## 5. 风险与回滚

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 写错电流/电压导致过流/过压 | 编码 clamp（快充 ≤3150mA、输入 ≤4000mA、浮充 ≤4700mV）；写序先限流后使能；write-readback 校验；默认不写 |
| R2 | PC USB 口被拉爆（500mA 口要 1800mA）| 读 MUIC CHG_TYPE，`USB-SDP/DOWNSTREAM/SPECIAL-500MA/未知` 一律强制 500mA 上限 |
| R3 | 充电看门狗/写保护理解错 | unlock 有读回验证；WDTEN 清除 + WDTCLR kick；失败只 log+返回错误，不重试到底 |
| R4 | 电池温度/健康异常 | 不写 CNFG_01/10/11（定时器/温度阈值/热配置）保持 S-Boot 值；`temp` 由 FG 提供，测试时监控 |
| R5 | 改坏驱动导致启动异常 | 驱动只在 probe 读；写控制默认关闭；`charge_enable=0` 时行为与旧只读版等价 |
| R6 | 寄存器语义猜错（例如 CNFG_10/12 不该读）| 只读不写；真出错最多打印失败，不影响充电配置 |

**回滚（一行级）**：
- 运行时：`echo disable > .../charge_ctrl`（停充）或 `echo 0 > .../charge_enable`（且下次 boot 不再写）；
- 镜像级：重刷 p217+（旧只读版即可），或 `p226`。
