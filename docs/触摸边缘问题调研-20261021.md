## 三、坐标范围：4096x4096 是正确的

### 3.1 决定性证据（vendor DTS）

`exynos7420-zero_common.dtsi:832-833`（vendor 内核，我们机型的原始配置）：

```dts
stm,max_coords = <4095 4095>;	/* x y */
stm,grip_area = <512>;
```

**⇒ 芯片上报的确实是 0..4095 的 12 位原始值**，与 mainline 的
`touchscreen-size-x/y = <4096>` 完全一致。

### 3.2 反证（p249 事故）

曾把 `touchscreen-size-x/y` 改成面板分辨率 1440x2560（p249），
结果**触摸完全失效** —— 因为芯片报 0..4095，超出新范围的值全被
libinput 钳到边缘。已回滚（p248）。

### 3.3 vendor 驱动如何用这个值

`fts_ts.c:1887-1910`：

```c
of_property_read_u32_array(np, "stm,max_coords", coords, 2);
pdata->max_x = coords[0];    // 4095
pdata->max_y = coords[1];    // 4095

// 某些面板变体会被硬覆盖成 1439x2559（S6E3HF2_WQXGA 等），
// 但那是针对不同 LCD 型号，不适用于我们的 s6e3hf2_wqhd
```

## 四、vendor 的边缘处理机制：`grip_area`

### 4.1 机制

`exynos7420-zero_common.dtsi`：`stm,grip_area = <512>`（512/4096 = **12.5%**）

`fts_ts.c` 在软件层把坐标落在边缘 512 单位内的触摸标记为 grip（疑似手掌）：

```c
if (x < grip_area || x > max_x - grip_area)
    input_report_abs(input_dev, ABS_MT_GRIP, 1);   // 标记为 grip
else
    input_report_abs(input_dev, ABS_MT_GRIP, 0);
```

`ABS_MT_GRIP` 是 vendor 自定义 ABS code，交给 Samsung framework
决定是否丢弃（防误触）。

### 4.2 对 mainline 的含义

- vendor **降低了**边缘的响应（主动丢弃疑似手掌的边缘触摸）
- mainline stmfts 驱动**没有** grip 处理 → 理论上边缘应该更灵敏
- 所以边缘"卡"不是被 software 过滤造成的

## 五、结论与建议

### 5.1 结论

**边缘触控不如中心灵敏是触摸面板的物理特性**：

- 电容触摸屏边缘的感应电极面积小、与边框/屏蔽层的耦合弱
- 信号强度天然低于中心区域，需要更大的接触面积才能稳定检测
- 同款面板在 vendor ROM 上也存在类似现象（vendor 用 grip_area 主动
  管理边缘触摸，本身就说明边缘不可靠是已知问题）

### 5.2 已做的实用改善

1. **关热角 + 关顶栏自动隐藏** → 边缘触摸不再被 GNOME 抢走
2. **启用 Applications 菜单**（`apps-menu` 扩展）→ 顶栏有大号下拉按钮，
   比左上角 Activities 好点
3. **Dash to Dock `show-apps-at-top=true`** → 底部 Dock 有"显示应用"按钮

### 5.3 若仍不满意，可选方向

| 方向 | 可行性 | 风险 |
|---|---|---|
| 移植 vendor 的 grip_area 反向逻辑（放大边缘） | 中 | 会引入误触 |
| 加载 vendor 触摸固件 `tsp_stm/stm_z1.fw` | 低 | mainline 驱动不支持固件加载；强刷有变砖风险 |
| 调 `touchscreen-fuzz-x/y` 平滑边缘抖动 | 高 | 会略微增加延迟 |
| 接受硬件特性，改用大按钮 | 高 | 无 |
