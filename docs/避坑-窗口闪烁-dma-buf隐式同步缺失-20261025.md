# 避坑：窗口内部元素闪烁（dma-buf 隐式同步缺失）

日期：2026-10-25
设备：SM-G9209 / Exynos 7420，mainline 6.6，exynos-drm + panfrost

---

## 现象

- **窗口内部渲染的元素**（搜索框、卡片、光标）持续闪烁
- 闪的时候显示的是**上一帧的旧内容**
- **静止不动时也在闪**（文字光标闪烁这类小范围重绘就触发）
- 顶栏、壁纸、整个屏幕是稳定的
- 伴随滑动卡顿

## 根因链

```
① GTK4 / mutter 通过 panfrost（GPU）异步渲染到 dma-buf
   panfrost 的 job 提交会把 dma_fence 加进 GEM 对象的 resv

② 但 exynos 的 plane 从来没有 prepare_fb 钩子：
     static const struct drm_plane_helper_funcs plane_helper_funcs = {
         .atomic_check  = exynos_plane_atomic_check,
         .atomic_update = exynos_plane_atomic_update,
         .atomic_disable = exynos_plane_atomic_disable,
         /* 没有 prepare_fb！ */
     };
     exynos_plane_atomic_update() 直接编程扫描地址，**不等 GPU 的 fence**

③ ⇒ GPU 还在往 buffer 里画，exynos 已经开始扫描
   ⇒ 屏幕上出现"半渲染完"的帧 = 上一帧的旧内容 + 闪烁
   ⇒ 同时 buffer 复用没有同步，合成器帧率控制失效 ⇒ 滑动卡
```

## 修复

`drivers/gpu/drm/exynos/exynos_drm_plane.c`：

```c
#include <drm/drm_gem_atomic_helper.h>

static int exynos_plane_prepare_fb(struct drm_plane *plane,
				   struct drm_plane_state *new_state)
{
	if (!new_state->fb)
		return 0;

	return drm_gem_plane_helper_prepare_fb(plane, new_state);
}

static void exynos_plane_cleanup_fb(struct drm_plane *plane,
				    struct drm_plane_state *old_state)
{
	/* drm_gem_plane_helper_prepare_fb() 挂上的 fence 由
	 * drm_atomic_set_fence_for_plane() 接管，这里不需要释放。 */
}

static const struct drm_plane_helper_funcs plane_helper_funcs = {
	.atomic_check  = exynos_plane_atomic_check,
	.atomic_update = exynos_plane_atomic_update,
	.atomic_disable = exynos_plane_atomic_disable,
	.prepare_fb = exynos_plane_prepare_fb,   /* ← 新增 */
	.cleanup_fb = exynos_plane_cleanup_fb,   /* ← 新增 */
};
```

### 为什么这样就够了

`drivers/gpu/drm/drm_gem_atomic_helper.c:135`：

```c
usage = fence ? DMA_RESV_USAGE_KERNEL : DMA_RESV_USAGE_WRITE;
for (i = 0; i < state->fb->format->num_planes; ++i) {
	struct drm_gem_object *obj = drm_gem_fb_get_obj(state->fb, i);
	ret = dma_resv_get_singleton(obj->resv, usage, &new);   /* 取写 fence */
	...
}
state->fence = fence;
```

没有显式 fence 时取的是 **DMA_RESV_USAGE_WRITE** —— 正是 GPU 渲染完成的信号。

而 exynos 的 commit 路径是：

```c
.atomic_commit      = drm_atomic_helper_commit,          /* 内部会 wait_for_fences */
.atomic_commit_tail = drm_atomic_helper_commit_tail_rpm,
```

⇒ 完整链条：`prepare_fb 取 fence` → `atomic commit 等待 fence` → 才编程扫描地址。

## 命名坑（6.6 与旧版不同）

- 旧内核：`drm_gem_fb_prepare_fb()`（`drm_gem_framebuffer_helper.h`）
- **6.6：`drm_gem_plane_helper_prepare_fb()`（`drm_gem_atomic_helper.h`）**
- `drm_gem_fb_prepare_fb` 在 6.6 里已经不存在，直接用会 "implicit declaration"

## 另一个已修的项：面板 SET_TEAR_ON

`panel-tear-on.service`（`/usr/local/bin/panel-tear-on.sh`）在开机后发：

```sh
echo "35,00" > /sys/module/exynosdrm/parameters/dcs_send
```

原因：i80 命令模式的面板需要 `0x35`（MIPI_DCS_SET_TEAR_ON）才会在帧边界锁存 GRAM；
没开的话面板实时显示 GRAM 写入过程 → 撕裂。S-Boot 之后内核从未发过它。

`dcs_send` 是本轮新加的模块参数，可以在运行时发任意 DCS：

```sh
echo "35,00" > /sys/module/exynosdrm/parameters/dcs_send   # TE on VBLANK
echo "35,01" > /sys/module/exynosdrm/parameters/dcs_send   # TE on VBLANK+HBLANK
echo "34"    > /sys/module/exynosdrm/parameters/dcs_send   # TE off
```
