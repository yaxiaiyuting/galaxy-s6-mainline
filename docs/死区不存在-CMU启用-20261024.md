# "AXI 死区"不存在 —— 只有一个偏移不可访问（CMU 全部可启用）

日期：2026-10-24
设备：SM-G9209 / Exynos 7420，mainline 6.6

---

## 结论

**"AXI 死区"是误判。** 之前判定为"一读即死"的 6 个 CMU，实际**可读可写**；
真正不可访问的只有**每个 CMU 的 `+0x000` 偏移**（secure/未实现）。

已启用 `CMU_TOPC` / `CMU_TOP0` / `CMU_PERIC1`，**零 SEA、零黑屏**。

## 误判是怎么来的

项目 DTS 注释的依据是 uniLoader 探针那句 "cmu_top0 @0x105d0000 一读即死"。
而 `0x105d0000` 正好是 `CMU_TOP0 + 0x000`，那一格是 secure/未实现；
它的邻居 `+0x004 / +0x200 / +0x634` 全都正常。

**一个偏移死了，整个 64KB 块被判死刑 → 6 个 CMU 节点全 disabled，
hsi2c 的时钟树跟着被判"不可用"。**

## 实测数据（全部 rc=0，可重复两轮，内核 #302/#303）

| 地址 | 读回 | 含义 |
|---|---|---|
| `0x10570000` | `0x00000384` | CMU_TOPC+0x000 `CC_PLL_LOCK` = 900（**连基址都可读**） |
| `0x10570200` / `0x10570400` | `0x00021111` / `0x00021111` | TOPC `MUX_SEL` / `MUX_STAT`（**相等 ⇒ mux 稳定**） |
| `0x10570600` / `0x10570800` | `0x33110040` / `0x11111111` | TOPC `DIV_TOPC0` / ACLK 门控全开 |
| `0x105D0004` | `0x0000012C` | TOP0 `ISP_LOCK` = 300 |
| `0x105D0200` | `0x00011111` | TOP0 `MUX_SEL_TOP00` |
| `0x105D0634` | `0x00900900` | **`DIV_TOP0_PERIC1`**，与 S-Boot 写值一字不差 |
| `0x105D0808` | `0xFFFFFFFF` | TOP0 ACLK 门控全开 |
| `0x14C80200` | `0x00000001` | PERIC1 `MUX_SEL_PERIC1_0`（= S-Boot 写值） |
| `0x14C80900` | `0x1F1FFFF0` | PERIC1 PCLK 门控 |
| `0x13650004` / `0x13670004` | `0x00080083` | **hsi2c_1 / hsi2c_7 控制器寄存器有内容** |
| `0x105E0200` / `0x105B0200` / `0x13610200` | `0x00011110` / `0x3` / `0x00010001` | TOP1 / CCORE / PERIC0 的 MUX_SEL 也可读 |

**写测试也通过**（同值回写 + 回读一致）：
`0x105D0200`、`0x105D0634`、`0x10570800`、`0x14C80900`、`0x13650004`、`0x13650000`
⇒ **CCF 完全可以接管这些时钟。**

## 真正不可访问的（实测 rc=139 / SEA）

1. **各 CMU 的 `+0x000`**：TOP0 / TOP1 / CCORE / PERIC0 / PERIC1
   （**注意 `CMU_TOPC + 0x000` 例外，它可读**）
2. **未实现偏移**：`+0x600`（PERIS / PERIC1 / TOP0）、`TOPC + 0x2000`、`PMU + 0x2C60`
3. **TZPC 块 `0x10100000 + 0x10000*i`（i=0..8）**
   S-Boot 字符串 `set_tzpc_secureport` 已证实其身份，`DECPROT_LOCK = 7`（已锁定）
4. **★ `pinctrl@14CE0000`（hsi2c 的 pinmux）** —— 连 `+0x000/+0x004` 都 SEA
   ⇒ **PMIC 的 i2c 必须继续走 i2c-gpio，无法换成硬件 hsi2c**

## 已做的启用（p360，内核 #304）

`exynos7420-zeroflte.dts`：
```dts
&{/soc@0/clock-controller@10570000} { status = "okay"; };  /* CMU_TOPC  */
&{/soc@0/clock-controller@105d0000} { status = "okay"; };  /* CMU_TOP0  */
&{/soc@0/clock-controller@14c80000} { status = "okay"; };  /* CMU_PERIC1 */
/* TOP1 / CCORE / PERIC0 保持 disabled（+0x000 SEA，且当前不需要） */
```

**驱动侧安全性（关键）**：`exynos7` 时钟驱动用到的寄存器偏移从 `0x0200` 起，
**从不读 `+0x000`**，所以 probe 不会触发 SEA。

**实测验证：**
```
时钟树里 32 个 peric1/topc 时钟正常注册：
  aclk_peric1_66 / dout_aclk_peric1_66 / mout_aclk_peric1_66
  ffac_topc_bus0_pll_div2 / ffac_topc_bus1_pll_div2
  ffac_topc_cc_pll_div2 / ffac_topc_mfc_pll_div2
SEA / Oops / Internal error: 0 个
显示 DPMS=On、背光正常、桌面 shell=2 VT=tty2、WiFi 正常
```

## 方法学（重要，应进项目工具规范）

1. **失败模式是 SEA（synchronous external abort, ESR `0x96000210`），不是"总线挂死"**
   DECERR ⇒ 被拒绝/未实现；真挂住 ⇒ 没时钟。
2. **arm64 的 `do_sea()` 不查异常表**，所以 `copy_from_kernel_nofault` / `probe_kernel_read`
   **救不了 SEA**（实测 Oops 就落在 `copy_from_kernel_nofault+0x9c`）。
   正确姿势：`ioremap` + 严格 4 字节访问 + **每条探测放独立子进程**
   （`timeout 4 sh -c "echo R $a > /proc/exytest"`），SEA 只死那个 shell，
   `panic_on_oops=0` 时系统不重启。
3. **这台机器上 `reboot` 会变成关机**（需人工上电）。
   可靠重启：`sync; echo b > /proc/sysrq-trigger`。
4. **别用 mmap 大块读 CMU**：Normal memory 语义可能一次读整条 cache line，
   碰到相邻不存在的寄存器更容易挂。Device memory 语义（`ioremap` + `readl`）严格 4 字节。

## 后续可做

1. **用真实时钟替换 fixed-clock**（`hsi2c7_clk` / `hsi2c5_clk` 等）
2. **`clk_disable_unused()` 风险**：会关掉没人用的门控，可能误关显示/i2c
   → 必要时在 driver 侧加 `CLK_IGNORE_UNUSED`（注意 cmdline 已有 `clk_ignore_unused`）
3. **hsi2c_1/7 的控制器可访问，但 pinmux 不可访问** → 若 S-Boot 已把引脚 mux 成 i2c 功能，
   仍可试硬件 i2c；否则保持 i2c-gpio
4. TOP1 / CCORE / PERIC0 当前不需要，保持 disabled
