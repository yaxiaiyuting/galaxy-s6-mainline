# DECON i80 TE 同步实现（消除画面撕裂）

日期：2026-10-24
设备：SM-G9209 / Exynos 7420，mainline 6.6，面板 S6E3HF2

---

## 问题

拖动窗口、滚动列表、播放动画时画面明显撕裂/闪烁。

## 三个假设的裁决

| 假设 | 结论 |
|---|---|
| DECON 的 TE 中断（`VIDINTCON0` bit15-14 = `I80_TE_MASK`） | ❌ **错**。bit15-14 实际是 `FRAMESEL0`（帧中断采样点选择）；`VIDINTCON1` bit2 `INT_I80` 是 i80 **帧完成**中断。DECON 里**没有**独立 TE 中断源，`TRIGCON` 也没有 0x10 的 `TE_SYNC` 位（bit0-6 已全部用完）。 |
| 面板 TE GPIO | ✅ **唯一真实路径 = GPG0[0]** |
| DSIM 报告 TE | ❌ **错**。7420 的 `regs-dsim.h` 全文**没有任何 TE 寄存器**（只有 `DSIM_INTSRC_RX_DAT_DONE` bit18 / `DSIM_INTSRC_ERR_RX_ECC` bit15）。 |

## TE 硬件路径（五条证据互锁）

```
面板 S6E3HF2 TE 引脚
  → SoC 焊盘 GPG0[0]
  → pinctrl_bus0 (0x13470000) EINT 块
  → GIC SPI 383
  → irq 69 "drm_decon_te"
```

**决定性证据 —— 寄存器地址逐位吻合：**

mainline `drivers/pinctrl/samsung/pinctrl-exynos.h`：
```
EXYNOS_GPIO_EPEND_OFFSET = 0xA00
EXYNOS_GPIO_EMASK_OFFSET = 0x900
```
mainline `pinctrl-exynos-arm64.c:321`：
```c
EXYNOS_PIN_BANK_EINTG(2, 0x1a0, "gpg0", 0x34)
```
算出：
```
EINT_PEND = 0x13470000 + 0xA00 + 0x34 = 0x13470A34  ←→ vendor te_eint reg[0]
EINT_MASK = 0x13470000 + 0x900 + 0x34 = 0x13470934  ←→ vendor te_eint reg[1]
te_pend_mask = bit0 → gpg0-0
```

与 vendor DTS（`exynos7420-zero_display_00.dtsi`）完全一致：
```dts
decon_0: decon_fb {
    gpios = <&gpg0 0 0xf>;          /* EINT for TE */
    te_eint {
        reg = <0x13470A34 0x4>, <0x13470934 0x4>;
        te_pend_mask = <0x00000001>;
    };
};
```

**其他证据：**
- `exynos7.dtsi:462` `pinctrl_bus0: pinctrl@13470000` 带 `interrupts = <GIC_SPI 383 IRQ_TYPE_LEVEL_HIGH>`
- mainline `exynos_irq_request_resources()` 申请 IRQ 时**自动把该脚切到 EINT 功能**（不需要改 pinctrl 驱动）
- `exynos7-pinctrl.dtsi:171` 已有 `gpg0: gpg0-gpio-bank` 标签
- vendor 引脚命名：`PIN_SLP(gpg0-0, PREV, NONE); /* DISPLAY_TE */`
- vendor ISR `decon-int_drv.c:852 decon_fb_isr_for_eint()`：TE 中断既喂 `vsync_info` 时间戳（SurfaceFlinger 的 vsync 源），又在 SW_TRIG 模式下用 TE 边沿打 `SWTRIGCMD`

## 实现

### DTS（`exynos7420-zeroflte.dts` 的 `&decon`）
```dts
te-gpios = <&gpg0 0 GPIO_ACTIVE_HIGH>;
```

### 驱动（`drivers/gpu/drm/exynos/exynos7_drm_decon.c`）
- `te_sync`（默认 **0**）、`te_debug`（默认 1）模块参数
- `decon_te_init()`：`devm_gpiod_get_optional(dev,"te",GPIOD_IN)` → `gpiod_to_irq()` → `devm_request_irq(IRQF_TRIGGER_RISING)`
- `decon_te_irq()`：计数 + 记录 jiffies + 诊断打印；`te_sync=1` 且有等待帧时打一次 `SWTRIGCMD`
- `decon_te_fallback_fn()`：40ms 兜底定时器，TE 不来就直接触发（等价旧行为，**不会黑屏/卡死**）
- `decon_atomic_flush()`：`te_sync && te_alive` 时延迟触发，否则**逐字节保持原逻辑**

### 持久化
`/etc/modprobe.d/exynosdrm-te.conf`：
```
options exynosdrm te_sync=1 te_debug=1
```

## 已知遗留问题

1. **`drm_decon`（i80 帧完成中断）计数为 0** —— 该中断可能未使能，需要单独查
2. **原 `decon_atomic_flush()` 里 `SWTRIGCMD` 被写了两次**（一次随 `val`，一次单独补脉冲）→ 每次 flush 可能发两帧，DSI 带宽翻倍。TE 验证通过后应去掉双脉冲
3. **`TRIGCON` 同时置 `SWTRIGEN` 和 `HWTRIGEN|HWTRIGMASK0/1`**（S-Boot 留下的 `0x2079` 也是），若 S-Boot 把 gpg0-0 留在功能 2，DECON 会**同时**被 TE 硬件和 SW 触发 → 应清掉 HWTRIGEN 位，只留 `SWTRIGEN`
4. **DSI 带宽可能不足**：1440x2560@60、24bpp 需 ≈5.3 Gbps，vendor `timing,dsi-hs-clk = <1026>`（4 lane × 1026 Mbps ≈ 4.1 Gbps）**跑不满 60fps 全帧刷新** —— 若 TE 有效但仍撕裂，多半是链路饱和
