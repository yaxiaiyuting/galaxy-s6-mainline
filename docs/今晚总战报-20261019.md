## 三、可选优化：GPU 硬件加速（p210）

**问题**：panfrost autosuspend（50ms）后 genpd 把 `pd_g3d` 断电；resume 时
`samsung,exynos5433-pd` 通用序列缺 vendor 的 G3D 上电步骤 → 读 0x14AC0000 → **SError → panic**
（实测：p207 在 26.46s，`gnome-shell` PID 375，`panfrost_gpu_soft_reset+0x34`）

**近路（p210，1 行 DTS）**：
```diff
&gpu {
-    status = "disabled";
+    status = "okay";
+    /delete-property/ power-domains;
};
```
**原理**：gpu 节点不挂 power-domains ⇒ genpd 永不断电；`pd_ignore_unused` 让它保持上电。
补丁已备：`display-p210-gpu-no-pd.patch`（已 `git apply --check`）

**彻底方案**：移植 vendor `pm_domains-exynos7420.c` 的 G3D 上电序列
（TOP0/TOPC1 门控 + pd-option=0x1101 + save_list 恢复），但 **TOP0 0x105d0000 本板实测读挂死**，
需要先 loader 探测。

## 十、最终结论（2026-10-19 04:50）

### 已用硬件实测证明的完整链路

```
S-Boot（初始化 DECON/DSIM/panel，持续扫描 0xe2a00000 的 1440x2560 fb）
  → uniLoader（裸机，武装看门狗）
  → mainline Linux 6.6（8 核 SMP + CNTPCT 定时器 + PID1 handover）
  → Debian 12（systemd running）
  → GNOME 43（simpledrm KMS + llvmpipe 软件渲染）
  → USB ECM 网络（26MB/18s）+ WiFi 5GHz（-53dBm, 802.11ac）
```

### 三个"本来以为很难"其实很简单的点

1. **显示**：不需要移植 exynos_drm/DSI。S-Boot 已经把硬件配好，
   Linux 只需要 `simpledrm` 把内存往 fb 里写 —— **绕开所有未上电 IP 的雷区**。
2. **定时器**：不是 MCT、不是 arch_timer 竞争，是 **CNTVOFF_EL2 固件没初始化**。
   4 行 workaround 解决。
3. **WiFi**：PCIe/PHY/固件全都一次就对。唯一的问题是**另一个子系统（GPU）在崩**，
   把排查方向带偏了两小时。

### 唯一真正需要"硬啃"的遗留

**panfrost GPU 电源序列**（vendor 的 G3D 上电：TOPC1 门控 + sys_pwr ×7 + pd-option=0x1101 + save_list）
- 近路：`&gpu { status="okay"; /delete-property/ power-domains; }`（p210，补丁已备）
- 彻底：移植 vendor 序列，但需先 loader 探测 `0x10570A04`（CMU_TOPC，本板未实测）

**⇒ 但对"能用的 GNOME 手机"来说，llvmpipe 软件渲染已经够了 ✓**
