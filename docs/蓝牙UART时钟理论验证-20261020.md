# 蓝牙 HCI reset 超时 —— 根因理论验证（UART 时钟差 9.77 倍）

日期：2026-10-20
状态：**理论已完全验证，待硬件确认**

---

## 一、现象

```
[   30.5] Bluetooth: hci0: command 0x0c03 tx timeout
[   38.6] Bluetooth: hci0: BCM: Reset failed (-110)
```

已排除：
- ✅ BT_EN 已拉高（`gpio-178 (gpioset) out hi`）
- ✅ UART 时钟已使能（btattach 期间 `sclk_uart 1 1 0 ... Y`）
- ✅ `/dev/ttySAC0` 存在，UART 引脚 gpz1-0..3 已 mux 为 `bt-uart-bus`
- ✅ `hci_bcm` H4 协议已注册，`btattach -P bcm` 正常 attach
- ✅ BT 固件已放 `/lib/firmware/brcm/`

⇒ 排除以上之后，**只剩波特率不对**。

## 二、决定性证据：vendor 的 UART SCLK 真实频率

`ctc_stock.dts:4303-4319`（vendor 3.10 内核 DTS）：

```dts
uart@11460000 {
    compatible = "samsung,exynos7420-uart";
    samsung,separate-uart-clk;
    clocks = <0x16 0x1a0 0x16 0x1b0 0x16 0x1c7>;
    clock-names = "gate_pclk4", "gate_uart4", "sclk_uart4";
    samsung,lpass-subip;
    uart-sclk-frequency = <0x6f94740>;      // ★ = 117,000,000 Hz
    status = "okay";
};
```

**`0x6f94740 = 117,000,000`**（正好 117 MHz 整）

## 三、分频链推导

CMU_AUD（`0x114C0000`）的时钟链（`clk-exynos7.c:1315-1330`）：

```c
PNAME(mout_aud_pll_user_p) = { "fin_pll", "fout_aud_pll" };
DIV(0, "dout_aud_cdclk",  "mout_aud_pll_user", DIV_AUD1, 24, 4);  // bits[27:24]
DIV(0, "dout_sclk_uart",  "dout_aud_cdclk",    DIV_AUD1, 12, 4);  // bits[15:12]
GATE(SCLK_UART, "sclk_uart", "dout_sclk_uart", ENABLE_SCLK_AUD, 29, 0, 0);
```

手机上实测（`/sys/kernel/debug/clk/clk_summary`）：

```
fout_aud_pll        48,000,000   ← 我们之前填的 fixed-clock
  mout_aud_pll_user 48,000,000
    dout_aud_cdclk  24,000,000   (÷2)
      dout_sclk_uart 12,000,000  (÷2)
        sclk_uart    12,000,000
```

⇒ 分频值是 **2 和 2**，所以：

```
sclk_uart = fout_aud_pll / 2 / 2
```

要让 `sclk_uart = 117 MHz`：

```
fout_aud_pll = 117,000,000 × 2 × 2 = 468,000,000 Hz = 468 MHz
```

**⇒ 468/2/2 = 117,000,000，与 vendor 值误差 0.0004%** ✓

## 四、为什么 48 MHz 会致命（核心）

驱动 `drivers/tty/serial/samsung_tty.c:1518-1575` 的
`s3c24xx_serial_getclk()`：

```c
rate = clk_get_rate(clk);          // 我们告诉内核的速率
if (!rate) { ... continue; }
if (info->has_divslot) {
    unsigned long div = rate / req_baud;   // 117e6 或 12e6
    quot = div / 16;                       // 写进 UBRDIV
    baud = rate / div;                     // 驱动认为的波特率
}
```

### 旧配置（48 MHz PLL → clk 树报 12 MHz）

| 步骤 | 值 |
|---|---|
| `clk_get_rate()` | 12,000,000 |
| `div = 12e6 / 115200` | **104** |
| `quot = 104/16` | **6** → 写进 UBRDIV 寄存器 |
| 驱动认为 baud | 12e6/104 = 115,384 ✓（看起来对） |
| **但硬件真实时钟** | **117,000,000** |
| **实际线上波特率** | **117e6 / 104 = 1,125,000** ❌ |

**⇒ 实际速率是 115200 的 9.77 倍。BCM4358 收到的是乱码，
HCI reset 命令无法解析 → 永远不回 ACK → tx timeout。**

### 新配置（468 MHz PLL → clk 树报 117 MHz）

| 步骤 | 值 |
|---|---|
| `clk_get_rate()` | 117,000,000 |
| `div = 117e6 / 115200` | **1015** |
| `quot = 1015/16` | **63** → UBRDIV |
| `baud = 117e6/1015` | **115,270** |
| 误差 | **0.06%** ✓ |

## 五、为什么之前没发现

1. `base_baud = 0` 是个**误导信号** —— 它来自 `uart_add_one_port()`
   打印的 `port->uartclk / 16`，而 `samsung-uart` 驱动**从不设置
   `port->uartclk`**（只在 `s3c24xx_serial_init_port()` 里设成 `1`）。
   所以 `base_baud = 0` 在这颗驱动上是**正常现象**，不是时钟缺失的证据。
2. `sclk_uart` 在 `clk_summary` 里显示 12 MHz 看起来"合理"，
   但它是**从我们填的 fixed-clock 算出来的**，不是硬件真值。
3. 没有 UART 回环测试，无法直接观察线上波形。

## 六、修复

`arch/arm64/boot/dts/exynos/exynos7420-zeroflte.dts`：

```dts
fout_aud_pll: clock-aud-pll {
    compatible = "fixed-clock";
    #clock-cells = <0>;
    clock-frequency = <468000000>;   /* 原 48000000 → 468 MHz */
    clock-output-names = "fout_aud_pll";
};
```

镜像：**p246**（`out/p246-padded.img`，Samsung sha1 `585bc7ceb2b1a3f13ccc631b8a21819214237a0f`）

### 如果还是超时（备选方案）

1. **试其他波特率**：117e6 下 921600 的分频 = 117e6/921600 = 127（整数！）
   ⇒ 如果 115200 不行，试 `btattach -S 921600`
2. **检查 UART 回环**：把 gpz1-0 (TX) 和 gpz1-1 (RX) 短接，发数据看能否收到
   （需要硬件操作，但只需一根镊子/跳线，不需要示波器）
3. **检查 vendor 的 `samsung,lpass-subip` 处理**：
   主线驱动可能缺少 LPASS 域的特殊初始化（上电/解除隔离）

## 八、结论

**根因：`fout_aud_pll` fixed-clock 填了 48 MHz（音频典型值），
而 BT UART 实际需要 117 MHz（vendor DTS 明确给出
`uart-sclk-frequency = 0x6f94740`）。分频链 /2/2 意味着 PLL 必须是
468 MHz。差 9.77 倍导致 UART 线上波特率变成 1.1 Mbaud，
芯片无法解析 HCI 命令。**

修复只改一个数值，零风险（其他 AUD 时钟我们不使用）。
