## 1. 一句话方案

**DECON 是我们的人，DSIM 是 S-Boot 的通讯兵。** 不去接管 DSIM（不写 PLL/PHY/CONFIG、不重跑初始化），
只借用它现成的 **SFR FIFO** 往面板发 3 条 DCS 短包：

| 目的 | DCS | 依据 |
|---|---|---|
| 熄屏时**真正灭掉发光** | `0x28`（display off） | vendor `s6e3hf2_wqhd_param.h:142 SEQ_DISPLAY_OFF` |
| 唤醒/点亮 | `0x29`（display on） | 同上 `:138 SEQ_DISPLAY_ON` |
| 调亮度 | `0x53 0x20`（BCTRL=1）+ `0x51 <0..255>`（DBV） | MIPI 标准；**待设备验证**（vendor 未用过 0x51） |

挂接点选在 **DECON 的 DPMS 钩子**（`decon_atomic_enable/disable`），因为：
1. GNOME 熄屏/唤醒一定经过这里（调研 §2.1 有完整调用链）；
2. `CONFIG_DRM_EXYNOS7_DECON=y` 是内建，**不需要跨模块导出符号**（避免 builtin↔module 依赖地狱）；
3. 复用项目已有的 `DSH-DISP` 调试风格与 kill-switch 习惯，回滚只要一个 `modprobe` 参数。

## 2. 方案 A 设计

### 2.1 架构

```
GNOME 熄屏
  └─ DPMS off → exynos_drm_crtc_atomic_disable()            [exynos_drm_crtc.c:37]
       └─ decon_atomic_disable()                            [exynos7_drm_decon.c:754]
            ├─ ★ dsh_dsim_display(ctx, false)   → DSIM SFR FIFO → DCS 0x28   ← 新增
            ├─ decon_disable_plane() ×2（关 window）
            └─ pm_runtime_put_sync()（关 DECON 时钟）

GNOME 唤醒
  └─ DPMS on → exynos_drm_crtc_atomic_enable()              [exynos_drm_crtc.c:21]
       └─ decon_atomic_enable()                             [exynos7_drm_decon.c:671]
            ├─ pm_runtime_resume + SYSMMU identity + decon_commit()
            └─ ★ dsh_dsim_display(ctx, true) → DCS 0x29
               ★ dsh_dsim_set_level(brightness) → 0x53 0x20 / 0x51 N   ← 新增

用户拖亮度条
  └─ logind → /sys/class/backlight/s6e3hf2/brightness
       └─ dsh_bl_update_status() → dsh_dsim_set_level()        ← 新增
```

面板**从未**被 mainline 复位或重新初始化 ⇒ 不存在"初始化序列写错 → 黑屏 → TWRP"的风险。

### 2.2 DCS 发送时序（纯轮询，不抢中断、不改配置）

```
dsh_dsim_wait_empty(SFR_HEADER_EMPTY, 2ms)     ← FIFOCTRL bit22
writel(header, DSIM_PKTHDR)                    ← 0x3c: ID | DATA0 | DATA1
dsh_dsim_wait_empty(SFR_HEADER_EMPTY, 20ms)    ← 排空 == 包已上 lane
```

长包（阶段 2 的 gamma 用得上）：

```
wait(SFR_HEADER_EMPTY | SFR_PAYLOAD_EMPTY)
for each 4B: writel(word, DSIM_PAYLOAD)        ← 0x40
writel(ID | WC<<8, DSIM_PKTHDR)                ← WC = payload 字节数
wait(SFR_HEADER_EMPTY); wait(SFR_PAYLOAD_EMPTY)
```

**只读 `STATUS`/`FIFOCTRL`，只写 `PKTHDR`/`PAYLOAD`。** 不写 `FIFOCTRL`（低 5 位会复位 FIFO）、
不写 `CONFIG/PLL/PHY` —— 这三样一动就得重跑 S-Boot 的初始化。

### 2.3 状态机（避免"熄屏时被改亮度"把面板点亮）

```c
update_status():  if (ctx->panel_off) return 0;   /* 只记住 props.brightness，不发包 */
                  else dsh_dsim_set_level(props.brightness);

atomic_disable(): 发 0x28，置 panel_off = true
atomic_enable():  发 0x29，panel_off = false，再 dsh_dsim_set_level(props.brightness)
```

### 2.4 三个 kill-switch（默认值 = 可以直接用，但先跑只读档）

| 参数 | 默认 | 作用 |
|---|---|---|
| `backlight=0` | 1 | 彻底关掉本功能（**等价于打补丁前的行为**，回滚第一选择） |
| `bl_dump=1` | 0 | 只在 probe 读一次 `DSIM_STATUS/FIFOCTRL`，**不注册 backlight、不发任何包**（上机第一步） |
| `bl_level=N` | 160 | 初始亮度 0..255 |

另外还有一道硬门禁：`dsh_bl_register()` 里读 `DSIM_STATUS`，若等于 `0xffffffff`
（总线活着但 IP 状态不对）就**直接放弃并 iounmap**，不写任何包。

## 3. 补丁逐块说明

完整 diff 见 `patches/display/0001-dsh-dsim-backlight.patch`。以下只列关键块。

### 3.1 板级 DTS：给 DECON 加第二个 reg 窗口

```dts
/* arch/arm64/boot/dts/exynos/exynos7420-zeroflte.dts */
&decon {
	status = "okay";

	reg = <0x13930000 0x10000>, <0x13900000 0x1000>;   /* ← DECON + DSIM0 */
	dsh,dsim-backlight;                                /* ← 功能开关（可删） */
	...
};
```

为什么用"DECON 的第二个 reg"而不是新节点/新驱动：
- `decon_probe()` 已经 `of_iomap(dev->of_node, 0)`，加 index 1 是零成本；
- 避免新 platform driver 与 DECON 抢同一个 DISP 电源域的引用计数；
- 不需要 export 任何符号（方案 A 的核心优势）。
- `iommus`/`interrupts` 等属性不受影响（它们不按 reg 索引）。

### 3.2 寄存器与位定义

```c
#define DSIM_STATUS		0x004
#define DSIM_PKTHDR		0x03c
#define DSIM_PAYLOAD		0x040
#define DSIM_FIFOCTRL		0x04c

#define DSIM_PKTHDR_ID(x)	((x) & 0x3f)
#define DSIM_PKTHDR_DATA0(x)	(((x) & 0xff) << 8)
#define DSIM_PKTHDR_DATA1(x)	(((x) & 0xff) << 16)

#define DSIM_SFR_HEADER_EMPTY	BIT(22)		/* 与 samsung-dsim.c:157-168 一致 */
#define DSIM_SFR_PAYLOAD_EMPTY	BIT(20)

#define DSH_DSI_DCS_SHORT_WRITE		0x05
#define DSH_DSI_DCS_SHORT_WRITE_PARAM	0x15
#define DSH_DSI_DCS_LONG_WRITE		0x39
```

offset 全部来自 vendor `decon_7420/regs-dsim.h:21-158`（7420 与主线 exynos5433 的寄存器表同族：
`CONFIG=0x18`、`INTSRC=0x34`、`PKTHDR=0x3c`、`FIFOCTRL=0x4c`）。

### 3.3 短包/长包发送

```c
static int dsh_dsim_write_short(struct decon_context *ctx, u8 data_id, u8 p0, u8 p1)
{
	u32 val = DSIM_PKTHDR_ID(data_id) | DSIM_PKTHDR_DATA0(p0) |
		  DSIM_PKTHDR_DATA1(p1);
	int ret;

	ret = dsh_dsim_wait_empty(ctx, DSIM_SFR_HEADER_EMPTY, 2000);
	if (ret)
		return ret;

	writel(val, ctx->dsim_regs + DSIM_PKTHDR);

	/* header FIFO 排空 == 包已经发到 lane 上 */
	return dsh_dsim_wait_empty(ctx, DSIM_SFR_HEADER_EMPTY, 20000);
}
```

（长包版本见补丁，用于阶段 2 的 `0xCA` gamma 35 字节。）

### 3.4 亮度与熄屏

```c
static int dsh_dsim_set_level(struct decon_context *ctx, unsigned int level)
{
	u8 seq[2];
	int ret;

	if (!ctx->dsim_regs || !ctx->bl_dev)
		return 0;

	if (level > ctx->bl_dev->props.max_brightness)
		level = ctx->bl_dev->props.max_brightness;

	if (!ctx->bctrl) {				/* 只写一次 */
		seq[0] = MIPI_DCS_WRITE_CONTROL_DISPLAY;	/* 0x53 */
		seq[1] = 0x20;					/* BIT(5) = BCTRL */
		ret = dsh_dsim_dcs_write(ctx, seq, 2);
		if (ret)
			return ret;
		ctx->bctrl = true;
	}

	seq[0] = MIPI_DCS_SET_DISPLAY_BRIGHTNESS;		/* 0x51 */
	seq[1] = (u8)level;
	return dsh_dsim_dcs_write(ctx, seq, 2);
}

static int dsh_dsim_display(struct decon_context *ctx, bool on)
{
	u8 cmd = on ? MIPI_DCS_SET_DISPLAY_ON : MIPI_DCS_SET_DISPLAY_OFF;  /* 0x29 / 0x28 */
	int ret;

	if (!ctx->dsim_regs || !ctx->bl_dev)
		return 0;

	ret = dsh_dsim_dcs_write(ctx, &cmd, 1);
	if (ret) {
		pr_err(DSH_DISP_TAG " decon: DCS 0x%02x failed (%d)\n", cmd, ret);
		return ret;
	}
	ctx->panel_off = !on;
	pr_err(DSH_DISP_TAG " decon: panel display %s\n", on ? "ON" : "OFF");
	return 0;
}
```

**刻意不发 `0x10`（sleep in）**：进 sleep 要 `0x11` + 完整初始化序列才能回来，
而那个序列在 S-Boot 手里（调研 §3.6 已对比过：主线那套对 HF2 明显不够）。

### 3.5 backlight 设备

```c
props.type = BACKLIGHT_PLATFORM;     /* gsd/KDE 偏好 firmware→platform→raw，这里给 platform */
props.max_brightness = 255;          /* vendor UI_MAX_BRIGHTNESS */
props.brightness = min_t(unsigned int, dsh_disp_bl_level, 255);
props.power = FB_BLANK_UNBLANK;

bl = backlight_device_register("s6e3hf2", dev, ctx, &dsh_bl_ops, &props);
...
dsh_dsim_set_level(ctx, bl->props.brightness);   /* 立刻下发一次，验证通道是否通 */
```

设备名 `s6e3hf2` ⇒ `/sys/class/backlight/s6e3hf2/{brightness,max_brightness,actual_brightness}`，
logind/GNOME/KDE 都能直接用。

### 3.6 DPMS 钩子（两处，共 8 行）

```c
/* decon_atomic_disable() 开头 */
	dsh_dsim_display(ctx, false);      /* 先灭面板，再关 window */

/* decon_atomic_enable() 结尾（ctx->suspended = false 之后） */
	if (ctx->bl_dev) {
		dsh_dsim_display(ctx, true);
		dsh_dsim_set_level(ctx, ctx->bl_dev->props.brightness);
	}
```

顺序很重要：熄屏时**先**发 DCS 再关 window/时钟（此时 DSIM 的 pclk 一定在），
唤醒时**后**发 DCS（此时 DECON 已经恢复扫描，i80 通路已活）。

## 5. 验证步骤

### 5.1 V1（零风险，先做，不需要补丁）：确认 300mA 就是面板发光

在**当前**系统（不需要任何新代码）里：

```sh
# 让屏幕显示全黑（任意一种）
feh --fullscreen /dev/null        # 或 gdk-pixbuf 任意全黑图
# 或用 GNOME：打开一张全黑图片全屏
```

等 5 秒，对比电流：

- 亮屏（GNOME 桌面）≈ -346mA
- 全黑图 ≈ **-100mA 以下** ⇒ 归因成立，`0x28` 会得到同样收益，方案 A 值得做

> 这一步的价值：用 5 分钟、零风险，证伪/证实整个方案的前提。

## 6. 退化与增强

### 6.1 如果 0x51 无效（BCTRL 不被支持）—— 阶段 2：gamma 简表

不改架构，只把 `dsh_dsim_set_level()` 的实现换成 gamma 路径（**长包发送函数已经写好**）：

```c
/* 伪代码：在 dsh_dsim_set_level 里替换 0x53/0x51 分支 */
u8 buf[36] = { 0xca, };
memcpy(buf + 1, gamma_tbl[index], 35);        /* index = level * (N-1) / 255 */
dsh_dsim_dcs_write(ctx, buf, 36);             /* 0xCA 长包 */
u8 upd[2] = { 0xf7, 0x03 }; dsh_dsim_dcs_write(ctx, upd, 2);
ndelay(100);
u8 upd0[2] = { 0xf7, 0x00 }; dsh_dsim_dcs_write(ctx, upd0, 2);
```

三档实现可选（风险由低到高）：

1. **借主线 HA2 表**（`panel-samsung-s6e3ha2.c:30-215`，46 档 × 35B = 1610 字节）：
   亮度能变，但白点/伽马是 HA2 的 ⇒ 会偏色。**先用它做可行性验证**。
2. **vendor 表的中间档插值**：从 `s6e3hf2_wqhd_dimming.h` 抽 8~16 个档位的 `gamma[36]`，
   中间线性插值（`interpolation_gamma_to_hbm()` 的思路，`s6e3hf2_wqhd_lcd_ctrl.c:559-630`）。
   需要写个离线小脚本从 vendor 头文件里把数组 dump 出来（`dimming_info[]` 的 `.gamma` 在 init 时才算，
   头文件里是 `rTbl/cTbl/aid/elv` 原始表 + `center_gamma`，所以实际要照搬 `init_dimming()` 的算法）。
3. **完整 Smart Dimming 移植**：要读面板 ID + MTP（`0xC8`）+ HBM gamma（`0xB4`）⇒
   **需要 DSI 读（BTA/LP turnaround）**，风险陡增，只有在 1/2 都不满意时才做。

### 6.2 亮度曲线（0x51 可用时）

`0x51` 的 0..255 是线性 DBV，但人眼是感知对数；建议用户态用
`brightnessctl --device=s6e3hf2 set 40%` 之类，或在内核里加一张查表把
"感知亮度"映射到 DBV（`props.max_brightness = 100` + 内部查表）。
**先不做**，等 V5 确认后再决定（否则是给没验证的通道加复杂度）。

### 6.3 如果 V7 出现花屏（i80 被插队）

在发 DCS 前把 DECON 的 i80 触发短暂静默（只碰我们自己拥有的 DECON）：

```c
/* 进：清 TRIGCON 的 SWTRIGCMD，等当前帧走完（约 1 帧 = 16.7ms）*/
val = readl(ctx->regs + TRIGCON);
writel(val & ~(TRIGCON_SWTRIGCMD_I80_RGB | TRIGCON_SWTRIGEN_I80_RGB),
       ctx->regs + TRIGCON);
usleep_range(17000, 20000);
/* ...发 DCS... */
/* 出：恢复原来的 TRIGCON 值 + 补一次触发 */
```
vendor 的等价物是 `decon_lpd_block_exit()`（`dsim_drv.c:239`）。**V7 过了就别加**（多一次帧停顿会有肉眼可见的一抖）。

### 6.4 方案 A0（备选：完全不碰 DSIM，让面板"扫描黑帧"）

如果 V2 发现 `DSIM_STATUS=0xffffffff`（DSIM 不能用），但**核心目标（熄屏省电）还得实现**，
可以走 A0：不动 DSIM，只让 DECON 持续扫描一块**全黑 framebuffer**，面板就会一直显示黑色 →
AMOLED 发光 ≈ 0 ⇒ 那 300mA 照样省掉。代价是 DECON/DSIM 仍空转（约 15–25mA），但没有亮度控制。

实现要点（改 `exynos7_drm_decon.c`，约 60 行）：

```c
/* probe: 分配一块全尺寸黑 buffer，并拿到它的 IOVA */
ctx->black_fb = dma_alloc_coherent(dev, 1440 * 2560 * 4, &ctx->black_pa, GFP_KERNEL);
ctx->black_iova = exynos_drm_fb_dma_get_dma_addr(...);   /* 走 DECON 同一个 IOMMU 域 */

/* decon_atomic_disable(): 不发 DCS，改成扫描黑帧，且不关时钟 */
writel(ctx->black_iova, ctx->regs + VIDW_BUF_START(0));
decon_trigger_i80(ctx);        /* 复用 flush 里那段 TRIGCON 触发 */
return;                        /* ★ 不 pm_runtime_put_sync() */

/* decon_atomic_enable(): 恢复真 fb（commit/update_plane 会重设 VIDW_BUF_START） */
```

诚实评估：

| 项 | 评价 |
|---|---|
| 硬件风险 | **零**（不访问 DSIM，只用自己的 DECON 寄存器） |
| 省电 | 好（面板发光 ≈ 0），比方案 A 多 15–25mA 的 DECON/DSIM 空转 |
| 亮度控制 | 无（只能"黑"或"正常"） |
| 内存 | +14.7 MB（1440×2560×4）长期占用 |
| 复杂度 | 中：要绕开 `pm_runtime_put`，还要和 DRM 的 CRTC-off 状态机对齐（vblank 已 off 但仍会来 `lcd_sys` 中断） |
| 何时用 | 只有 V2 判定 DSIM 不可用、且不接受方案 C 的"唤醒要重启"时才做 |

> 判断顺序依旧是：**A（可调亮度+可唤醒）→ A0（只省电）→ C（要重启）→ B（长期）**。

## 7. 方案 C：关面板供电（兜底 / 测量工具）

脚本：`rootfs/display/g9209-panel-power.sh`

```sh
g9209-panel-power.sh idetect    # 扫所有 i2c 总线上的 0x59 / 0x60
g9209-panel-power.sh probe      # 只读：MAX77838 ID / STAT(POK) / EN(LDO1..4)
g9209-panel-power.sh off        # 清 REG_EN bit0|bit2 → 面板两路 LDO 断电（保留触摸屏两路）
g9209-panel-power.sh on         # 恢复（供电回来，画面仍需重启）
```

原理（调研 §6.1）：MAX77838 @ `0x60`，`reg 0x03 REG_REG_EN` bit0=LDO1(`VCC_DISPLAY_1.8V`)、
bit2=LDO3(`VCC_3.0V_LCD`)；`reg 0x02 REG_REG_STAT` 回读 POK。脚本只清 bit0|bit2，
**保留 bit1(LDO2 tsp_io)/bit3(LDO4 tsp_avdd)**，否则触摸屏一起断电、唤醒后还得重跑
`g9209-touch-power.sh`。

### 7.1 三个必须先知道的事实

1. **0x60 不一定 ACK**：板级 DTS 自己的注释（`exynos7420-zeroflte.dts:952-953`）写着
   "mainline 实测只有 0x59 稳定 ACK"。脚本第一句就是 `find_bus()`，摸不到就直接退出，不写任何寄存器。
2. **断电 = 画面回不来**：`VCC_3.0V_LCD` 掉了 DDI 就 POR，S-Boot 的初始化序列没人重放
   （调研 §6.3）。`on` 只把电送回来，屏幕仍然黑，**必须重启**。
3. 所以它**不是**"熄屏节能"方案，只是：①测面板真实功耗；②长期不用时省电；③方案 A 失败时的应急。

### 7.2 什么时候用它

| 场景 | 用不用 |
|---|---|
| 测量"面板全暗"到底省多少（给方案 A 定 KPI） | ✅ `off` 前后看电流 |
| 方案 A 的 V3 失败（0x28 无效）且急需省电 | ✅ 但每次唤醒要重启 |
| 日常熄屏/唤醒 | ❌（画面回不来） |

## 8. 方案 B：移植 DSI + 面板驱动（长期，只有 A 不够时才做）

### 8.1 要做的事（按顺序，每步都可单独验证）

1. **DSIM 节点**（`exynos7.dtsi` 或板级 DTS 新增）：
   ```dts
   dsi_0: dsi@13900000 {
       compatible = "samsung,exynos5433-mipi-dsi";   /* 7420 与 5433 寄存器同族 */
       reg = <0x13900000 0x1000>;
       interrupts = <GIC_SPI 196 IRQ_TYPE_LEVEL_HIGH>;
       clocks = <&cmu_disp CLK_PCLK_DSIM0>, <&cmu_disp …mipi0_bit…>;
       clock-names = "pclk_dsim0", "sclk_mipi0";
       samsung,burst-clock-frequency = <1026000000>;  /* vendor timing,dsi-hs-clk=1026 */
       samsung,esc-clock-frequency = <16000000>;      /* vendor timing,dsi-escape-clk=16 */
       #address-cells = <1>; #size-cells = <0>;
       status = "okay";
       panel@0 { compatible = "samsung,s6e3hf2"; reg = <0>; … };
   };
   ```
   注意 `exynos_drm_dsi.c` 的 `of_match` **没有 7420**，要用 5433 的 compatible
   或者自己加一个 `.compatible = "samsung,exynos7420-mipi-dsi", .data = &exynos5433_dsi_pdata`。
2. **DECON 不再需要 `i80-if-timings`**（DSI 桥进 pipeline 后由 `exynos_dsi_host_attach()`
   （`exynos_drm_dsi.c:34-61`）把 `crtc->i80_mode` 设为 `!(mode_flags & MIPI_DSI_MODE_VIDEO)`，
   s6e3ha2 的 mode_flags 里**没有** `MIPI_DSI_MODE_VIDEO` ⇒ 自动是 i80，行为一致）。
3. **面板驱动**：`panel-samsung-s6e3ha2.c` 已有 `samsung,s6e3hf2`，但：
   - mode 要改成 **1440×2560**（现在是 1600×2560，`:627-643`）；
   - `enable()`/`prepare()` 的初始化序列要按 vendor `s6e3hf2_wqhd_init()`
     （`s6e3hf2_wqhd_lcd_ctrl.c:1451`，180 行）重写；
   - 亮度要接 `dsim_backlight.c` 的 73 档 gamma（含 MTP 读取）。
4. **风险点**：
   - DSIM 的 PLL/PHY 参数：`dsim_reg_7420.c` 的 `dphy_timing[]` 表（1026 Mbps/lane）必须搬对；
   - `samsung_dsim_init_link()`（`samsung-dsim.c:835`）会 `FIFOCTRL &= ~0x1f` 复位 FIFO、重写 CONFIG，
     **接管瞬间屏幕必然黑一下**；
   - 任一步错 ⇒ 黑屏 + 只能 TWRP 救（面板已被复位，S-Boot 的状态没了）。

### 8.2 结论

**方案 B 的收益 = 亮度可调范围完整**（A 已经有熄屏和可能的 0x51 亮度）。
只有 V5 失败、且用户不能接受"借 HA2 gamma 表偏色"时才值得做。
不做也不影响"熄屏真正省电"这个主要目标。

## 9. 回滚

| 层级 | 操作 | 影响 |
|---|---|---|
| 最轻（运行中） | `modprobe -r exynosdrm; insmod …exynosdrm.ko backlight=0` | 立刻回到打补丁前行为 |
| 中（运行中，只读诊断） | `insmod …exynosdrm.ko bl_dump=1` | 只读一次寄存器，不发包 |
| 内核 | DTS 删 `dsh,dsim-backlight;` 与第二个 `reg` | 驱动走 `!of_property_read_bool()` 直接返回 |
| 最彻底 | `git apply -R patches/display/0001-dsh-dsim-backlight.patch` + 重刷 | 恢复原状 |
| 紧急（屏卡死/花屏） | 长按电源重启（S-Boot 重建 DSIM/面板状态） | 不需要 TWRP |

永久性配置建议放 `/etc/modprobe.d/g9209-exynosdrm.conf`：

```
options exynosdrm backlight=1 bl_level=160
```

（exynosdrm 是模块：`CONFIG_DRM_EXYNOS=m`，见 `显示bring-up-20261019.md` §4。）

## 10. 风险总表

| 风险 | 概率 | 后果 | 缓解 |
|---|---|---|---|
| 0x28 被 DDI 忽略，电流不掉 | 低 | 熄屏仍费电 | V3 判读；退化到方案 C/A0 |
| 0x51/BCTRL 不支持 | **中** | 亮度不可调（熄屏仍有效） | §6.1 阶段 2 gamma |
| DCS 插队导致偶发花屏 | 中 | 视觉瑕疵 | §6.3 TRIGCON 静默 |
| DSIM 被写坏 | 低 | 屏冻/花，需重启 | 只碰 SFR FIFO；`bl_dump` 先验证；`backlight=0` 兜底 |
| DSIM 寄存器访问挂总线 | **很低** | 需物理复位 | STATUS 全 1 门禁；pclk 有 `CLK_IGNORE_UNUSED`；bootargs `clk_ignore_unused` |
| 唤醒后屏不回来 | 中 | 需重启 | 不发 0x10（不进 sleep）；V4 专门验证 |
| GNOME 不显示亮度条 | 低 | 只能命令行调 | `type=BACKLIGHT_PLATFORM`；`ls /sys/class/backlight` 先确认 |
| 与 GNOME DPMS 时序打架（熄屏后又被 update_status 点亮） | 低 | 熄屏失败 | `panel_off` 状态机（§2.3） |

## 11. 待设备恢复后必须回答的问题（无法离线确定）

1. `DSIM_STATUS` 的实际值（V2）—— 决定方案 A 是否成立；
2. 0x28 是否真的能停发光（V3）—— 决定核心目标；
3. 0x51/BCTRL 是否被支持（V5）—— 决定亮度是"可调"还是"只有开关"；
4. 快速改亮度会不会花屏（V7）—— 决定要不要加 LPD 协调；
5. MAX77838 `0x60` 到底 ACK 不 ACK（V8）—— 决定方案 C 能不能用；
6. 面板在"全暗但扫描中"的功耗（V1 与 V3 对比）—— 给后续优化定基线。

以上任何一项的实测结果变了，本文档的推荐顺序就要跟着调（当前推荐：**A → A0/C → B**）。
