## 四、⚠️ LOS20 时代的关键未解问题

**内核侧已成功，但 I2C 0x2b 不应答：**

```
✅ 开机正常（不再 panic —— 之前两个驱动抢同一组 GPIO 才崩）
✅ /dev/pn547 创建成功（crw-rw---- nfc nfc 10,44）
✅ 6-002b 绑定到 pn547 驱动
❌ I2C 0x2b 仍不应答
```

### 排查方向（按优先级）

1. **电源没开**：`VDD20_1P8_AP` LDO 需要 enable。查 vendor DTS 里该 regulator 的定义和 `regulator-boot-on` / `always-on` 属性
2. **ven_gpio 没拉高**：PN547 需要 VEN 拉高才响应 I2C。查 vendor DTS 里 `pn547,ven-gpio` / `pn547,firm-gpio` 的 GPIO 编号和默认电平
3. **I2C 总线时钟门控在死区**（**最大嫌疑**）：
   - `hsi2c@14E00000` 的门控很可能在 **CMU_PERIC1（0x14C80000）**，而那是本板 AXI 死区
   - 如果是这样，**必须改用 i2c-gpio**（参考电池驱动的成功方案：`gpd2-2/3` 已验证可用）
   - 或者查 vendor 有没有别的 I2C 控制器接 NFC
4. **pinctrl 没配**：I2C 引脚的上拉/驱动强度
5. **芯片需要先下载固件才响应**：PN547 在 ROM 模式下 I2C 是响应的（用于下载固件），但如果 VEN 时序不对可能不响应

## 五、🔑 mainline 路线的重大优势

**LOS20 时代的最终障碍是 Android HAL ABI 不兼容**：
- 原厂 NXP HAL 导出 `phNxpNciHal_open` / `HMI` 结构体
- LOS 20 的 HAL 服务只认 C++ `device_open`（三星 S.LSI 库的 API）
- **这个在 mainline 上完全不存在！**

mainline 的 NFC 栈是：
```
neard (userspace daemon，Debian 有包)
  ↕ netlink / /dev/nfc0
nxp-nci 驱动（drivers/nfc/nxp-nci/，主线官方支持 PN547）
  ↕ I2C
PN547
```

**⇒ 所以 mainline 上 NFC 最大的障碍不是 HAL，而是「I2C 0x2b 不应答」这个硬件/电源问题**

## 七、硬件安全约束

- **死区（绝对不能碰）**：
  - `0x14C00000`–`0x14CE0000`（含 0x14C80000/0x14C90000/0x14CA0000/0x14CE0000）
  - `0x10570000`（CMU_TOPC）、`0x105D0000`（CMU_TOP0）
  - `0x13650000`（hsi2c_1）
- **`hsi2c@14E00000`（0x14E00000）本身不在死区**，但它的时钟门控很可能在 CMU_PERIC1（0x14C80000 死区）
- 未实测地址不要从内核直接读
